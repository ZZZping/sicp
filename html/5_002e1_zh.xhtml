5.1设计寄存器机器

要设计一台寄存器机器，我们必须设计它的 数据通路（寄存器和操作）以及对这些操作进行排序的 控制器。为了说明简单寄存器机器的设计，让我们考察欧几里得算法，它用于计算两个整数的最大公约数（GCD）。正如我们在 1.2.5 中看到的，欧几里得算法可以通过一个迭代计算过程来执行，如下过程所指定：

(define (gcd a b)
  (if (= b 0)
      a
      (gcd b (remainder a b))))

执行这个算法的机器必须跟踪两个数， a 和 b ，所以让我们假设这两个数存储在具有这些名字的两个寄存器中。所需的基本操作是测试寄存器 b 的内容是否为零，以及计算寄存器 a 的内容除以寄存器 b 的内容的余数。求余数操作是一个复杂的过程，但暂时假设我们有一个计算余数的基本设备。在 GCD 算法的每个循环中，寄存器 a 的内容必须被寄存器 b 的内容替换，而 b 的内容必须被 a 的旧内容除以 b 的旧内容的余数替换。如果这些替换能够同时完成会很方便，但在我们的寄存器机器模型中，我们将假设每一步只能给一个寄存器赋新值。为了完成这些替换，我们的机器将使用第三个“临时”寄存器，我们称之为 t。（首先将余数放入 t，然后将 b 的内容放入 a，最后将存储在 t 中的余数放入 b。）

我们可以用 图 5.1 中所示的数据通路图来说明这台机器所需的寄存器和操作。在这个图中，寄存器（a、b 和 t）用矩形表示。给寄存器赋值的每种方式都由一个箭头指示，箭头头部后面有一个 X，从数据源指向寄存器。我们可以把 X 看作一个按钮，当按下时，允许源处的值“流入”指定的寄存器。每个按钮旁边的标签是我们用来指代该按钮的名字。这些名字是任意的，可以选择具有助记价值（例如，a<-b 表示按下将寄存器 b 的内容赋给寄存器 a 的按钮）。寄存器的数据源可以是另一个寄存器（如 a<-b 赋值中），一个操作结果（如 t<-r 赋值中），或一个常量（一个不能改变的内置值，在数据通路图中用包含该常量的三角形表示）。

从常量和寄存器内容计算值的操作在数据通路图中用一个包含操作名称的梯形表示。例如，在图5.1中标记为rem的方框表示一个操作，它计算与其相连的寄存器a和b的内容的余数。箭头（不带按钮）从输入寄存器和常量指向方框，箭头将操作的输出值连接到寄存器。测试用一个包含测试名称的圆圈表示。例如，我们的GCD机器有一个操作，测试寄存器b的内容是否为零。测试也有来自其输入寄存器和常量的箭头，但它没有输出箭头；它的值由控制器使用，而不是由数据通路使用。总的来说，数据通路图显示了机器所需的寄存器和操作以及它们必须如何连接。如果我们把箭头看作导线，把X按钮看作开关，那么数据通路图就非常像一台可以用电子元件构建的机器的布线图。

为了使数据通路真正计算GCD，必须按正确的顺序按下按钮。我们将用控制器图来描述这个顺序，如图5.2所示。控制器图的元素指示应如何操作数据通路组件。控制器图中的矩形框标识要按下的数据通路按钮，箭头描述从一个步骤到下一个步骤的顺序。图中的菱形表示一个判定。根据菱形中标识的数据通路测试的值，将沿着两个顺序箭头之一进行。我们可以用物理类比来解释控制器：把图想象成一个迷宫，一颗弹珠在其中滚动。当弹珠滚入一个方框时，它按下该方框所命名的数据通路按钮。当弹珠滚入一个判定节点（例如测试b = 0）时，它根据所指示测试的结果沿着确定的路径离开该节点。数据通路和控制器一起完整地描述了一台计算GCD的机器。我们在寄存器a和b中放入数字后，在标记为start的位置启动控制器（滚动的弹珠）。当控制器到达done时，我们将在寄存器a中找到GCD的值。

习题5.1： 设计一台寄存器机器，使用以下过程指定的迭代算法来计算阶乘。画出这台机器的数据通路图和控制器图。

(define (factorial n)
  (define (iter product counter)
    (if (> counter n)
        product
        (iter (* counter product)
              (+ counter 1))))
  (iter 1 1))

5.1.1一种描述寄存器机器的语言

数据通路图和控制器图足以表示像GCD这样的简单机器，但对于描述像Lisp解释器这样的大型机器来说，它们就显得笨拙了。为了能够处理复杂的机器，我们将创建一种语言，以文本形式呈现数据通路图和控制器图给出的所有信息。我们将从一种直接反映这些图的记法开始。

我们通过描述寄存器和操作来定义机器的数据通路。为了描述一个寄存器，我们给它一个名称，并指定控制对其赋值的按钮。我们给每个这样的按钮一个名称，并指定在按钮控制下进入寄存器的数据来源。（来源是一个寄存器、一个常量或一个操作。）为了描述一个操作，我们给它一个名称，并指定它的输入（寄存器或常量）。

我们将机器的控制器定义为一个 指令序列，以及标识序列中 入口点的 标签。一条指令是以下之一：

  • 要按下的数据通路按钮的名称，用于给寄存器赋值。（这对应于控制器图中的一个方框。）
  • 一条test指令，执行指定的测试。
  • 根据前一个测试的结果，条件分支（branch指令）到由控制器标签指示的位置。（测试和分支一起对应于控制器图中的一个菱形。）如果测试为假，控制器应继续执行序列中的下一条指令。否则，控制器应继续执行标签之后的指令。
  • 一条无条件分支（goto指令），指定一个控制器标签，在该标签处继续执行。

机器从控制器指令序列的开头开始，当执行到达序列末尾时停止。除非分支改变了控制流，否则指令按列出的顺序执行。

图5.3展示了以这种方式描述的GCD机器。这个例子只是暗示了这些描述的普遍性，因为GCD机器是一个非常简单的例子：每个寄存器只有一个按钮，并且每个按钮和测试在控制器中只使用一次。

图5.3： ↓ GCD机器的规格说明。

(data-paths

             (source (register b)))))
  ((name b)
   (buttons ((name b<-t)
             (source (register t)))))

             (source (operation rem))))))

    (label gcd-done))  ; conditional branch

   (b<-t)              ; button push
   (goto

 gcd-done)             ; label

不幸的是，这样的描述很难阅读。为了理解控制器指令，我们必须不断回头查看按钮名称和操作名称的定义，而为了理解按钮做什么，我们可能又必须查看操作名称的定义。因此，我们将变换我们的表示法，把数据通路和控制器描述中的信息结合起来，以便能一起看到全部信息。

为了得到这种形式的描述，我们将用其行为的定义来替换任意的按钮和操作名称。也就是说，不再（在控制器中）说“按下按钮t<-r”，并另外（在数据通路中）说“按钮t<-r将rem操作的值赋给寄存器t”以及“rem操作的输入是寄存器a和b的内容”，我们将在（控制器中）说“按下那个将寄存器a和b的内容上rem操作的值赋给寄存器t的按钮”。类似地，不再（在控制器中）说“执行=测试”，并另外（在数据通路中）说“=测试对寄存器b的内容和常量0进行操作”，我们将说“对寄存器b的内容和常量0执行=测试”。我们将省略数据通路描述，只留下控制器序列。这样，GCD机器描述如下：

(controller
 test-b
   (test (op =) (reg b) (const 0))
   (branch (label gcd-done))
   (assign t (op rem) (reg a) (reg b))
   (assign a (reg b))
   (assign b (reg t))
   (goto (label test-b))
 gcd-done)

这种形式的描述比图5.3中所示的那种更容易阅读，但它也有缺点：

  • 对于大型机器来说，它更冗长，因为每当控制器指令序列中提到数据通路元件时，这些元件的完整描述都会被重复。（这在GCD例子中不是问题，因为每个操作和按钮只使用一次。）此外，重复数据通路描述会掩盖机器实际的数据通路结构；对于大型机器来说，有多少寄存器、操作和按钮以及它们如何互连并不明显。
  • 因为机器定义中的控制器指令看起来像Lisp表达式，所以很容易忘记它们并不是任意的Lisp表达式。它们只能表示合法的机器操作。例如，操作只能直接作用于常量和寄存器的内容，而不能作用于其他操作的结果。

尽管有这些缺点，我们将在本章中一直使用这种寄存器机器语言，因为我们更关心理解控制器，而不是理解数据通路中的元件和连接。然而，我们应该记住，数据通路设计在设计真实机器时是至关重要的。

习题5.2： 用寄存器机器语言描述习题5.1中的迭代阶乘机器。

动作

让我们修改GCD机器，以便我们可以输入想要计算GCD的数，并在终端上打印出答案。我们不讨论如何制造一台能读和打印的机器，而是假设（就像我们在Scheme中使用read和display时那样）它们可以作为基本操作使用。286

Read与我们一直使用的操作类似，因为它产生一个可以存储在寄存器中的值。但read不从任何寄存器获取输入；它的值取决于在我们所设计的机器部件之外发生的事情。我们将允许机器的操作具有这样的行为，因此将像绘制和表示任何其他计算值的操作一样来绘制和表示read的使用。

另一方面，Print与我们一直使用的操作有一个根本区别：它不产生要存储在寄存器中的输出值。虽然它有效果，但这个效果不在我们所设计的机器部件上。我们将把这种操作称为动作。我们将在数据通路图中像表示计算值的操作一样表示动作——用一个包含动作名称的梯形。箭头从任何输入（寄存器或常量）指向动作框。我们还为动作关联一个按钮。按下按钮使动作发生。为了让控制器按下一个动作按钮，我们使用一种称为perform的新指令。因此，打印寄存器a内容的动作在控制器序列中由以下指令表示

(perform (op print) (reg a))

图5.4显示了新GCD机器的数据通路和控制器。我们没有让机器在打印答案后停止，而是让它重新开始，这样它反复读取一对数，计算它们的GCD，并打印结果。这种结构类似于我们在第4章解释器中使用的驱动循环。

5.1.2机器设计中的抽象

我们经常定义机器时包含实际上非常复杂的“基本”操作。例如，在5.4和5.5中，我们将把Scheme的环境操作视为基本操作。这种抽象是有价值的，因为它允许我们忽略机器某些部分的细节，从而可以专注于设计的其他方面。然而，我们把大量复杂性掩盖起来这一事实并不意味着机器设计不现实。我们总是可以用更简单的基本操作来替换复杂的“基本”操作。

考虑GCD机器。该机器有一条指令，它计算寄存器a和b中内容的余数，并将结果赋给寄存器t。如果我们想在不使用基本余数操作的情况下构造GCD机器，就必须说明如何用更简单的操作（例如减法）来计算余数。事实上，我们可以按如下方式编写一个用这种方式求余数的 Scheme 过程：

(define (remainder n d)
  (if (< n d) n (remainder (- n d) d)))

因此，我们可以把GCD机器数据通路中的余数操作替换为一个减法操作和一个比较测试。图5.5展示了经此展开后的机器的数据通路和控制器。指令

(assign t (op rem) (reg a) (reg b))

在GCD控制器定义中，它被替换为一段包含循环的指令序列，如图5.6所示。

图5.6： ↓ 图5.5中GCD机器的控制器指令序列。

(controller
 test-b
   (test (op =) (reg b) (const 0))
   (branch (label gcd-done))
   (assign t (reg a))
 rem-loop
   (test (op <) (reg t) (reg b))
   (branch (label rem-done))
   (assign t (op -) (reg t) (reg b))
   (goto (label rem-loop))
 rem-done
   (assign a (reg b))
   (assign b (reg t))
   (goto (label test-b))
 gcd-done)

5.1.3子程序

在设计一台执行计算的机器时，我们通常更希望安排计算的不同部分共享组件，而不是复制组件。考虑一台包含两个GCD计算的机器——一个求寄存器a和b中内容的GCD，另一个求寄存器c和d中内容的GCD。我们可能先假设有一个基本gcd操作，然后用更基本的操作展开gcd的两个实例。图5.7只展示了所得机器数据通路中的GCD部分，没有展示它们如何连接到机器的其余部分。该图还展示了机器控制器序列的相应部分。

这台机器有两个余数操作框和两个相等性测试框。如果被复制的组件很复杂，比如余数框，那么这不会是一种经济的机器构造方式。只要这样做不会影响更大的机器其余部分的计算，我们就可以通过让两个GCD计算使用相同的组件来避免复制数据通路组件。如果在控制器到达gcd-2时不再需要寄存器a和b中的值（或者这些值可以移到其他寄存器中妥善保存），我们就可以修改机器，使得在计算第二个GCD时也像计算第一个那样使用寄存器a和b，而不是寄存器c和d。如果这样做，就得到图5.8所示的控制器序列。

对于处理小问题来说，这是一种合理的方法，但如果控制器序列中有许多GCD计算的实例，它就会变得很笨拙。为了决定在gcd子程序之后从哪里继续执行，我们需要在数据通路中为所有使用gcd的地方设置测试，并在控制器中设置分支指令。实现子程序的一种更强大的方法是让continue寄存器保存控制器序列中入口点的标签，当子程序结束时，执行应从该入口点继续。实现这一策略需要在寄存器机器的数据通路和控制器之间建立一种新型连接：必须有一种方法，能把控制器序列中的一个标签赋给某个寄存器，使得这个值可以从该寄存器中取出，并用于在指定的入口点继续执行。

为了体现这一能力，我们将扩展寄存器机器语言的 assign 指令，允许将一个寄存器赋值为控制器序列中的一个标签（作为一种特殊的常量）。我们还将扩展 goto 指令，允许执行从寄存器内容所描述的入口点继续，而不仅仅是从常量标签所描述的入口点继续。使用这些新构造，我们可以通过跳转到存储在 continue 寄存器中的位置来终止 gcd 子程序。这导致了 图 5.10 中所示的控制器序列。

5.1.4使用栈实现递归

借助到目前为止所展示的思想，我们可以通过指定一个寄存器机器来实现任何迭代计算过程，该机器有一个与计算过程的每个状态变量相对应的寄存器。机器反复执行一个控制器循环，改变寄存器的内容，直到满足某个终止条件。在控制器序列的每一点，机器的状态（表示迭代计算过程的状态）完全由寄存器的内容（状态变量的值）决定。

然而，实现递归计算过程需要一种额外的机制。考虑下面这个计算阶乘的递归方法，我们最初在 1.2.1 中考察过它：

(define (factorial n)
  (if (= n 1) 
      1
      (* (factorial (- n 1)) n)))

正如我们从该过程所看到的，计算 n ! 需要计算 ( n − 1 ) ! 。我们的 GCD 机器仿照该过程

(define (gcd a b)
  (if (= b 0) 
      a
      (gcd b (remainder a b))))

同样必须计算另一个 GCD。但是，将原始计算归约为一个新的 GCD 计算的 gcd 过程，与需要计算另一个阶乘作为子问题的 factorial 之间，有一个重要区别。在 GCD 中，新的 GCD 计算的答案就是原始问题的答案。为了计算下一个 GCD，我们只需将新的参数放入 GCD 机器的输入寄存器中，并通过执行相同的控制器序列来重用机器的数据通路。当机器完成求解最终的 GCD 问题时，它就完成了整个计算。

在阶乘（或任何递归计算过程）的情况下，新的阶乘子问题的答案不是原始问题的答案。为 ( n − 1 ) ! 得到的值必须乘以 n 才能得到最终答案。如果我们试图模仿 GCD 的设计，通过递减 n 寄存器并重新运行阶乘机器来求解阶乘子问题，我们将不再拥有用于乘以结果的 n 的旧值。因此，我们需要第二台阶乘机器来处理子问题。这第二次阶乘计算本身又有一个阶乘子问题，这需要第三台阶乘机器，依此类推。由于每台阶乘机器内部都包含另一台阶乘机器，整个机器包含一个无限嵌套的相似机器，因此无法由固定、有限数量的部件构造出来。

尽管如此，如果我们能够安排对机器的每个嵌套实例使用相同的组件，我们就可以将阶乘计算过程实现为寄存器机器。具体来说，计算 n ! 的机器应该使用相同的组件来处理计算 ( n − 1 ) ! 的子问题、计算 ( n − 2 ) ! 的子问题，等等。这是合理的，因为尽管阶乘计算过程要求使用数量没有上限的相同机器副本来执行计算，但在任何给定时刻只需要其中一份处于活动状态。当机器遇到递归子问题时，它可以暂停主问题上的工作，重用相同的物理部件来处理子问题，然后继续被暂停的计算。

在子问题中，寄存器的内容将与主问题中的内容不同。（在这种情况下，n 寄存器被递减。）为了能够继续被暂停的计算，机器必须保存子问题解决后所需的所有寄存器的内容，以便可以恢复这些内容以继续被暂停的计算。在阶乘的情况下，我们将保存 n 的旧值，以便在完成计算递减后的 n 寄存器的阶乘时恢复它。287

由于对嵌套递归调用的深度没有先验限制，我们可能需要保存任意数量的寄存器值。这些值必须按照与保存时相反的顺序恢复，因为在嵌套递归中，最后进入的子问题最先完成。这决定了要使用栈，即“后进先出”数据结构，来保存寄存器值。我们可以扩展寄存器机器语言，通过添加两种指令来包含栈：使用save指令将值放入栈中，使用restore指令从栈中恢复值。在一系列值被save到栈上之后，一系列restore将按相反顺序取回这些值。288

借助栈，我们可以为每个阶乘子问题重用阶乘机器数据通路的单一副本。在重用操作数据通路的控制器序列时也存在类似的设计问题。为了重新执行阶乘计算，控制器不能像迭代计算过程那样简单地循环回开头，因为在求解 ( n − 1 ) ! 子问题之后，机器仍然必须将结果乘以 n 。控制器必须暂停其对 n ! 的计算，求解 ( n − 1 ) ! 子问题，然后继续其对 n ! 的计算。这种对阶乘计算的看法表明应使用5.1.3中描述的子程序机制，该机制让控制器使用continue寄存器转移到序列中求解子问题的部分，然后在主问题上从离开的地方继续。因此，我们可以制作一个阶乘子程序，返回到存储在continue寄存器中的入口点。在每次子程序调用前后，我们保存和恢复continue，就像我们对n寄存器所做的那样，因为阶乘计算的每个“层级”都将使用相同的continue寄存器。也就是说，阶乘子程序在为一个子问题调用自身时必须将新值放入continue，但它将需要旧值以便返回到调用它求解子问题的位置。

图5.11展示了实现递归factorial过程的机器的数据通路和控制器。该机器有一个栈和三个寄存器，分别称为n、val和continue。为了简化数据通路图，我们没有命名寄存器赋值按钮，只命名了栈操作按钮（sc和sn用于保存寄存器，rc和rn用于恢复寄存器）。要操作该机器，我们将希望计算其阶乘的数放入寄存器n并启动机器。当机器到达fact-done时，计算完成，答案将在val寄存器中找到。在控制器序列中，n和continue在每次递归调用之前被保存，并在调用返回时恢复。从调用返回是通过分支到存储在continue中的位置来完成的。Continue在机器启动时初始化，以便最后一次返回将转到fact-done。保存阶乘计算结果的val寄存器在递归调用之前不被保存，因为val的旧内容在子程序返回后没有用处。只需要新值，即子计算产生的值。

尽管原则上阶乘计算需要无限机器，但图5.11中的机器实际上是有限的，除了栈可能无界。然而，任何特定的物理栈实现都将具有有限大小，这将限制机器可以处理的递归调用深度。这个阶乘实现说明了将递归算法实现为用栈增强的普通寄存器机器的一般策略。当遇到递归子问题时，我们将子问题解决后需要其当前值的寄存器保存到栈上，求解递归子问题，然后恢复保存的寄存器并继续在主问题上执行。continue寄存器必须始终保存。是否需要保存其他寄存器取决于特定机器，因为并非所有递归计算都需要在子问题求解期间被修改的寄存器的原始值（见习题5.4）。

双重递归

让我们考察一个更复杂的递归计算过程，即斐波那契数的树形递归计算，我们在1.2.2中介绍过它：

(define (fib n)
  (if (< n 2) 
      n 
      (+ (fib (- n 1)) (fib (- n 2)))))

就像阶乘一样，我们可以将递归斐波那契计算实现为带有寄存器n、val和continue的寄存器机器。该机器比阶乘机器更复杂，因为控制器序列中有两个地方需要执行递归调用——一次计算 Fib ( n − 1 ) ，一次计算 Fib ( n − 2 ) 。为了为每个调用做准备，我们保存稍后需要其值的寄存器，将n寄存器设置为需要递归计算其Fib的数（ n − 1 或 n − 2 ），并将主序列中要返回的入口点（分别为afterfib-n-1或afterfib-n-2）赋给continue。然后我们转到fib-loop。当我们从递归调用返回时，答案在val中。图5.12展示了该机器的控制器序列。

图5.12： ↓ 计算斐波那契数的机器的控制器。

(controller
   (assign continue (label fib-done))
 fib-loop
   (test (op <) (reg n) (const 2))
   (branch (label immediate-answer))
   ;; set up to compute Fib(n − 1)
   (save continue)
   (assign continue (label afterfib-n-1))
   (save n)           ; save old value of n
   (assign n 
           (op -)
           (reg n)
           (const 1)) ; clobber n to n-1
   (goto 
    (label fib-loop)) ; perform recursive call
 afterfib-n-1 ; upon return, val contains Fib(n − 1)
   (restore n)
   (restore continue)
   ;; set up to compute Fib(n − 2)
   (assign n (op -) (reg n) (const 2))
   (save continue)
   (assign continue (label afterfib-n-2))
   (save val)         ; save Fib(n − 1)
   (goto (label fib-loop))
 afterfib-n-2 ; upon return, val contains Fib(n − 2)
   (assign n 
           (reg val)) ; n now contains Fib(n − 2)
   (restore val)      ; val now contains Fib(n − 1)
   (restore continue)
   (assign val        ; Fib(n − 1) + Fib(n − 2)
           (op +) 
           (reg val)
           (reg n))
   (goto              ; return to caller,
    (reg continue))   ; answer is in val
 immediate-answer
   (assign val 
           (reg n))   ; base case: Fib(n) = n
   (goto (reg continue))
 fib-done)

习题 5.6： Ben Bitdiddle 观察到 斐波那契 机器的控制器序列中多了一条 save 和一条 restore，去掉它们可以使机器更快。这些指令在哪里？

5.1.5指令摘要

我们的寄存器机器语言中的控制器指令具有下列形式之一，其中每个 ⟨ i n p u t i ⟩ 要么是 (reg ⟨register-name⟩) 要么是 (const ⟨constant-value⟩)。这些指令是在 5.1.1 中引入的：

(assign ⟨register-name⟩ (reg ⟨register-name⟩))
(assign ⟨register-name⟩ 
        (const ⟨constant-value⟩))
(assign ⟨register-name⟩ 
        (op ⟨operation-name⟩) 
        ⟨input₁⟩ … ⟨inputₙ⟩)
(perform (op ⟨operation-name⟩) 
         ⟨input₁⟩ 
         … 
         ⟨inputₙ⟩)
(test (op ⟨operation-name⟩) 
      ⟨input₁⟩ 
      … 
      ⟨inputₙ⟩)
(branch (label ⟨label-name⟩))
(goto (label ⟨label-name⟩))

使用寄存器保存标签的做法是在 5.1.3 中引入的：

(assign ⟨register-name⟩ (label ⟨label-name⟩))
(goto (reg ⟨register-name⟩))

使用栈的指令是在 5.1.4 中引入的：

(save ⟨register-name⟩)
(restore ⟨register-name⟩)

到目前为止我们所见到的唯一一种 ⟨constant-value⟩ 是数，但以后我们还会使用字符串、符号和表。例如，
(const "abc") 是字符串 "abc"，
(const abc) 是符号 abc，
(const (a b c)) 是表 (a b c)，
而 (const ()) 是空表。
