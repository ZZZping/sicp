4.2Scheme 的变体——惰性求值

既然我们有了一个用 Lisp 程序表达的求值器，我们就可以仅仅通过修改求值器来试验语言设计中的替代选择。事实上，新语言常常是通过首先编写一个将新语言嵌入现有高级语言中的求值器而发明的。例如，如果我们希望与 Lisp 社区的另一位成员讨论对 Lisp 提议修改的某个方面，我们可以提供一个体现该修改的求值器。接收者随后可以用新的求值器进行实验，并以进一步修改的形式反馈意见。高级实现基础不仅使测试和调试求值器更容易；此外，这种嵌入使设计者能够从底层语言中攫取235特性，正如我们嵌入的 Lisp 求值器使用底层 Lisp 的基本过程和控制结构一样。只有在后来（如果有的话），设计者才需要费心用低级语言或硬件构建完整的实现。在本节和下一节中，我们探讨 Scheme 的一些变体，它们提供了显著额外的表达能力。

4.2.1正则序与应用序

在1.1中，我们开始讨论求值模型时，我们注意到 Scheme 是一种 应用序语言，即，Scheme 过程的所有参数在过程应用时都会被求值。相比之下， 正则序语言将过程参数的求值延迟到实际需要参数值时。将过程参数的求值延迟到最后一刻（例如，直到基本操作需要它们时）称为 惰性求值。236考虑过程

(define (try a b)
  (if (= a 0) 1 b))

在 Scheme 中求值(try 0 (/ 1 0))会产生错误。使用惰性求值，则不会有错误。求值该表达式将返回1，因为参数(/ 1 0)永远不会被求值。

一个利用惰性求值的例子是过程unless的定义

(define (unless condition 
                usual-value 
                exceptional-value)
  (if condition 
      exceptional-value 
      usual-value))

它可用于如下表达式中

(unless (= b 0)
        (/ a b)
        (begin 
          (display "exception: returning 0")
          0))

这在应用序语言中行不通，因为在调用unless之前，通常值和异常值都会被求值（比较习题1.6）。惰性求值的一个优点是，某些过程，例如unless，即使对其某些参数的求值会产生错误或不会终止，也能进行有用的计算。

如果在参数被求值之前进入过程体，我们说该过程在该参数上是 非严格的。如果在进入过程体之前参数被求值，我们说该过程在该参数上是 严格的。237在纯应用序语言中，所有过程在每个参数上都是严格的。在纯正则序语言中，所有复合过程在每个参数上都是非严格的，而基本过程可能是严格的或非严格的。还有一些语言（见习题4.31）让程序员对他们定义的过程的严格性进行详细控制。

一个可以有效地使其非严格的引人注目的例子是cons（或者，一般来说，几乎任何数据结构的构造函数）。即使元素的值未知，也可以进行有用的计算，将元素组合成数据结构并对所得数据结构进行操作。例如，在不知道表中各个元素值的情况下计算表的长度是完全合理的。我们将在4.2.3中利用这一思想，将第3章的流实现为由非严格cons序对构成的表。

4.2.2带惰性求值的解释器

在本节中，我们将实现一种正则序语言，它与 Scheme 相同，只是复合过程对每个参数都是非严格的。基本过程仍然是严格的。修改 4.1.1 的求值器，使其解释的语言以这种方式行为，并不困难。几乎所有需要的更改都集中在过程应用上。

基本思想是，当应用一个过程时，解释器必须确定哪些参数需要求值，哪些需要延迟。被延迟的参数不求值；相反，它们被转换成称为 thunk 的对象。238 thunk 必须包含在需要时产生参数值所需的信息，就像它在应用时已经被求值一样。因此，thunk 必须包含参数表达式以及正在求值过程应用的环境。

对 thunk 中的表达式进行求值的过程称为 强制求值。239 一般来说，只有当 thunk 的值被需要时，它才会被强制求值：当它被传递给将使用 thunk 值的基本过程时；当它是条件表达式的谓词的值时；以及当它是即将作为过程被应用的运算符的值时。我们可以选择的一种设计是是否对 thunk 进行 记忆化，就像我们在 3.5.1 中对延迟对象所做的那样。使用记忆化，thunk 第一次被强制求值时，它会存储计算出的值。后续的强制求值只是返回存储的值，而不重复计算。我们将让解释器进行记忆化，因为这对许多应用来说更高效。然而，这里有一些棘手的考虑。240

修改求值器

惰性求值器与 4.1 中的求值器的主要区别在于 eval 和 apply 中对过程应用的处理。

eval 的 application? 子句变为

((application? exp)
 (apply (actual-value (operator exp) env)
        (operands exp)
        env))

这与 4.1.1 中 eval 的 application? 子句几乎相同。然而，对于惰性求值，我们使用运算对象表达式调用 apply，而不是使用对它们求值产生的参数。由于如果参数要被延迟，我们将需要环境来构造 thunk，因此我们也必须传递环境。我们仍然对运算符求值，因为 apply 需要实际要应用的过程，以便根据其类型（基本过程还是复合过程）进行分派并应用它。

每当我们需要表达式的实际值时，我们使用

(define (actual-value exp env)
  (force-it (eval exp env)))

而不是仅仅使用 eval，这样如果表达式的值是一个 thunk，它将被强制求值。

我们新版本的 apply 也与 4.1.1 中的版本几乎相同。区别在于 eval 传递的是未求值的运算对象表达式：对于基本过程（它们是严格的），我们在应用基本过程之前对所有参数求值；对于复合过程（它们是非严格的），我们在应用过程之前延迟所有参数。

(define (apply procedure arguments env)
  (cond ((primitive-procedure? procedure)
         (apply-primitive-procedure
          procedure
          (list-of-arg-values 
           arguments 
           env)))  ; changed
        ((compound-procedure? procedure)
         (eval-sequence
          (procedure-body procedure)
          (extend-environment
           (procedure-parameters procedure)
           (list-of-delayed-args 
            arguments 
            env)   ; changed
           (procedure-environment procedure))))
        (else (error "Unknown procedure 
                      type: APPLY" 
                     procedure))))

处理参数的过程与 4.1.1 中的 list-of-values 一样，只是 list-of-delayed-args 延迟参数而不是对它们求值，并且 list-of-arg-values 使用 actual-value 而不是 eval：

(define (list-of-arg-values exps env)
  (if (no-operands? exps)
      '()
      (cons (actual-value 
             (first-operand exps) 
             env)
            (list-of-arg-values 
             (rest-operands exps)
             env))))

(define (list-of-delayed-args exps env)
  (if (no-operands? exps)
      '()
      (cons (delay-it 
             (first-operand exps) 
             env)
            (list-of-delayed-args 
             (rest-operands exps)
             env))))

我们必须修改求值器的另一个地方是 if 的处理，在那里我们必须使用 actual-value 而不是 eval 来获取谓词表达式的值，然后再测试它是真还是假：

(define (eval-if exp env)
  (if (true? (actual-value (if-predicate exp) 
                           env))
      (eval (if-consequent exp) env)
      (eval (if-alternative exp) env)))

最后，我们必须修改 driver-loop 过程（4.1.4），使用 actual-value 而不是 eval，这样如果延迟值被传播回读取-求值-打印循环，它将在被打印之前被强制求值。我们还将提示符改为表明这是惰性求值器：

(define input-prompt  ";;; L-Eval input:")
(define output-prompt ";;; L-Eval value:")

(define (driver-loop)
  (prompt-for-input input-prompt)
  (let ((input (read)))
    (let ((output (actual-value 
                   input 
                   the-global-environment)))
      (announce-output output-prompt)
      (user-print output)))
  (driver-loop))

完成这些更改后，我们可以启动求值器并测试它。成功求值 4.2.1 中讨论的 try 表达式表明解释器正在执行惰性求值：

(define the-global-environment 
  (setup-environment))

(driver-loop)

;;; L-Eval input:
(define (try a b) (if (= a 0) 1 b))

;;; L-Eval value:
ok

;;; L-Eval input:
(try 0 (/ 1 0))

;;; L-Eval value:
1
表示 thunk

我们的求值器必须安排好在过程应用于参数时创建 thunk，并在以后强制求值这些 thunk。thunk 必须将表达式与环境打包在一起，以便以后可以产生参数。要强制求值 thunk，我们只需从 thunk 中提取表达式和环境，并在环境中对表达式求值。我们使用 actual-value 而不是 eval，这样如果表达式的值本身是一个 thunk，我们将强制求值它，依此类推，直到我们到达不是 thunk 的东西：

(define (force-it obj)
  (if (thunk? obj)
      (actual-value (thunk-exp obj) 
                    (thunk-env obj))
      obj))

将表达式与环境打包在一起的一种简单方法是创建一个包含表达式和环境的表。因此，我们如下创建 thunk：

(define (delay-it exp env)
  (list 'thunk exp env))
(define (thunk? obj) (tagged-list? obj 'thunk))
(define (thunk-exp thunk) (cadr thunk))
(define (thunk-env thunk) (caddr thunk))

实际上，我们为解释器想要的并不完全是这个，而是经过记忆化的 thunk。当一个 thunk 被强制求值时，我们将通过用其值替换存储的表达式并更改 thunk 标签以便它可以被识别为已经求值，从而将其转换为已求值的 thunk。241

(define (evaluated-thunk? obj)
  (tagged-list? obj 'evaluated-thunk))

(define (thunk-value evaluated-thunk) 
  (cadr evaluated-thunk))

(define (force-it obj)
  (cond ((thunk? obj)
         (let ((result
                (actual-value 
                 (thunk-exp obj)
                 (thunk-env obj))))
           (set-car! obj 'evaluated-thunk)
           ;; replace exp with its value:
           (set-car! (cdr obj) result) 
           ;; forget unneeded env:
           (set-cdr! (cdr obj) '()) 
           result))
        ((evaluated-thunk? obj)
         (thunk-value obj))
        (else obj)))

注意，同一个 delay-it 过程在有记忆化和无记忆化的情况下都能工作。

4.2.3流作为惰性表

在3.5.1中，我们展示了如何将流实现为延迟表。我们引入了特殊形式delay和cons-stream，它们允许我们构造一个计算流的cdr的“承诺”，而不实际履行该承诺直到以后。我们可以使用这种引入特殊形式的一般技术，每当我们需要对求值过程有更多控制时，但这很笨拙。一方面，特殊形式不像过程那样是一等对象，因此我们不能将其与高阶过程一起使用。243此外，我们被迫将流创建为一种新的数据对象，类似于表但不完全相同，这要求我们重新实现许多普通的表操作（map、append等）以供流使用。

使用惰性求值，流和表可以完全相同，因此不需要特殊形式或单独的表和流操作。我们只需要安排使得cons是非严格的。实现这一点的一种方法是扩展惰性求值器以允许非严格的基本过程，并将cons实现为其中之一。更简单的方法是回想（2.1.3）根本没有必要将cons实现为基本过程。相反，我们可以将序对表示为过程：244

(define (cons x y) (lambda (m) (m x y)))
(define (car z) (z (lambda (p q) p)))
(define (cdr z) (z (lambda (p q) q)))

根据这些基本操作，表操作的标准定义将适用于无限表（流）以及有限表，而流操作可以实现为表操作。以下是一些例子：

(define (list-ref items n)
  (if (= n 0)
      (car items)
      (list-ref (cdr items) (- n 1))))

(define (map proc items)
  (if (null? items)
      '()
      (cons (proc (car items))
            (map proc (cdr items)))))

(define (scale-list items factor)
  (map (lambda (x) (* x factor))
       items))

(define (add-lists list1 list2)
  (cond ((null? list1) list2)
        ((null? list2) list1)
        (else (cons (+ (car list1) 
                       (car list2))
                    (add-lists
                     (cdr list1) 
                     (cdr list2))))))

(define ones (cons 1 ones))

(define integers 
  (cons 1 (add-lists ones integers)))

;;; L-Eval input:
(list-ref integers 17)

;;; L-Eval value:
18

注意，这些惰性表甚至比第3章的流还要惰性：表的car以及cdr都被延迟了。245事实上，即使访问惰性序对的car或cdr也不必强制求值表元素的值。该值只有在真正需要时才会被强制求值——例如，用作基本过程的参数，或作为答案打印出来。

惰性序对还有助于解决在3.5.4中处理流时出现的问题，在那里我们发现，为带回路的系统建立流模型可能需要我们在程序中额外添加显式的delay操作，超出cons-stream所提供的那些。使用惰性求值，过程的所有参数都被统一延迟。例如，我们可以按照最初在3.5.4中的意图，实现用于对表进行积分和解微分方程的过程：

(define (integral integrand initial-value dt)
  (define int
    (cons initial-value
          (add-lists (scale-list integrand dt) 
                     int)))
  int)

(define (solve f y0 dt)
  (define y (integral dy y0 dt))
  (define dy (map f y))
  y)

;;; L-Eval input:
(list-ref (solve (lambda (x) x) 1 0.001) 1000)

;;; L-Eval value:
2.716924

238 thunk一词是由一个非正式工作组发明的，该工作组当时正在讨论Algol60中按名调用的实现。他们观察到，对表达式的大部分分析（“思考”）可以在编译时完成；因此，在运行时，该表达式已经被“thunk”过了（Ingerman等人1960）。

240 惰性求值结合记忆化有时被称为按需调用参数传递，与按名调用参数传递相对。（按名调用，在Algol60中引入，类似于非记忆化的惰性求值。）作为语言设计者，我们可以将求值器构建为记忆化的、非记忆化的，或者将此作为程序员的一个选项（习题4.31）。正如你可能从第3章中预期的那样，这些选择在存在赋值时会引发既微妙又令人困惑的问题。（见习题4.27和习题4.29。）Clinger（1982）的一篇优秀文章试图澄清这里出现的多个维度的困惑。
