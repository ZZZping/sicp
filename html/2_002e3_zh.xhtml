2.3符号数据

到目前为止我们使用过的所有复合数据对象最终都是由数字构造出来的。在本节中，我们通过引入将任意符号作为数据进行处理的能力，扩展了语言的表示能力。

2.3.1引用

如果我们能用符号构成复合数据，我们就可以有像这样的表

(a b c d)
(23 45 17)
((Norah 12) 
 (Molly 9) 
 (Anna 7) 
 (Lauren 6) 
 (Charlotte 4))

包含符号的表可以看起来就像我们语言的表达式：

(* (+ 23 45) (+ x 9))
(define (fact n) 
  (if (= n 1) 
      1 
      (* n (fact (- n 1)))))

为了操作符号，我们需要在语言中加入一个新元素： 引用一个数据对象的能力。假设我们想要构造表(a b)。我们无法用(list a b)做到这一点，因为这个表达式构造的是a和b的 值的表，而不是符号本身。这个问题在自然语言的语境中是众所周知的，其中词和句子可以被视为语义实体，也可以被视为字符串（句法实体）。自然语言中的常见做法是使用引号来表明一个词或一个句子应被字面地当作一串字符来处理。例如，“John”的第一个字母显然是“J”。如果我们对某人说“大声说出你的名字”，我们期望听到那个人的名字。然而，如果我们对某人说“大声说出‘你的名字’”，我们期望听到“你的名字”这几个词。注意，我们被迫嵌套引号来描述别人可能说的话。98

我们可以遵循同样的做法来标识那些应被当作数据对象而不是待求值表达式的表和符号。然而，我们的引用格式与自然语言不同之处在于，我们只在待引用对象的开头放置一个引号（传统上是单引号符号'）。在 Scheme 语法中我们可以这样做，因为我们依靠空白和括号来界定对象。因此，单引号字符的含义就是引用下一个对象。99

现在我们可以区分符号和它们的值：

(define a 1)
(define b 2)

(list a b)
(1 2)

(list 'a 'b)
(a b)

(list 'a b)
(a 2)

引用还允许我们使用表的常规打印表示来输入复合对象：100

(car '(a b c))
a

(cdr '(a b c))
(b c)

与此一致，我们可以通过求值'()来获得空表，从而省去变量nil。

在操作符号时使用的另一个基本过程是eq?，它接受两个符号作为参数并测试它们是否相同。101使用eq?，我们可以实现一个有用的过程，称为memq。它接受两个参数，一个符号和一个表。如果该符号不包含在表中（即，与表中的任何项都不eq?），那么memq返回假。否则，它返回从该符号第一次出现处开始的表的子表：

(define (memq item x)
  (cond ((null? x) false)
        ((eq? item (car x)) x)
        (else (memq item (cdr x)))))

例如，

(memq 'apple '(pear banana prune))

的值是假，而

(memq 'apple '(x (apple sauce) y apple pear))

的值是(apple pear)。

2.3.2示例：符号求导

作为符号操作的示例以及数据抽象的进一步示例，考虑设计一个执行代数表达式符号求导的过程。我们希望该过程接受一个代数表达式和一个变量作为参数，并返回该表达式对该变量的导数。例如，如果过程的参数是 a x 2 + b x + c 和 x ，过程应返回 2 a x + b 。符号求导在Lisp中具有特殊的历史意义。它是开发用于符号操作的计算机语言的动机示例之一。此外，它标志着导致开发强大的符号数学工作系统的研究路线的开端，这些系统目前正被越来越多的应用数学家和物理学家使用。

在开发符号求导程序时，我们将遵循与开发2.1.1中有理数系统时相同的数据抽象策略。也就是说，我们将首先定义一个求导算法，它操作诸如“和”、“积”和“变量”这样的抽象对象，而不必担心这些对象如何表示。只有之后我们才会处理表示问题。

使用抽象数据的求导程序

为了保持简单，我们将考虑一个非常简单的符号求导程序，它处理仅使用两个参数的加法和乘法运算构建的表达式。任何此类表达式的求导都可以通过应用以下归约规则来进行： d c d x = 0 , for  c  a constant  or a variable  different from  x , d x d x = 1 , d ( u + v ) d x = d u d x + d v d x , d ( u v ) d x = u d v d x + v d u d x . 注意后两条规则本质上是递归的。也就是说，为了得到和的导数，我们首先求出各项的导数并将它们相加。每一项又可能是一个需要分解的表达式。分解成越来越小的片段最终将产生要么是常量要么是变量的片段，它们的导数将是0或1。

为了将这些规则体现在一个过程中，我们进行一点一厢情愿的设想，就像我们在设计有理数实现时所做的那样。如果我们有表示代数表达式的手段，我们应该能够判断一个表达式是和、积、常量还是变量。我们应该能够提取表达式的部分。例如，对于一个和，我们希望能够提取加数（第一项）和被加数（第二项）。我们还应该能够从部分构造表达式。让我们假设我们已经有了实现以下选择函数、构造函数和谓词的过程：

(variable? e)          Is e a variable?
(same-variable? v1 v2) Are v1 and v2 the same variable?
(sum? e)               Is e a sum?
(addend e)             Addend of the sum e.
(augend e)             Augend of the sum e.
(make-sum a1 a2)       Construct the sum of a1 and a2.
(product? e)           Is e a product?
(multiplier e)         Multiplier of the product e.
(multiplicand e)       Multiplicand of the product e.
(make-product m1 m2)   Construct the product of m1 and m2.

使用这些，以及识别数字的基本谓词number?，我们可以将求导规则表达为以下过程：

(define (deriv exp var)
  (cond ((number? exp) 0)
        ((variable? exp)
         (if (same-variable? exp var) 1 0))
        ((sum? exp)
         (make-sum (deriv (addend exp) var)
                   (deriv (augend exp) var)))
        ((product? exp)
         (make-sum
          (make-product 
           (multiplier exp)
           (deriv (multiplicand exp) var))
          (make-product 
           (deriv (multiplier exp) var)
           (multiplicand exp))))
        (else (error "unknown expression 
                      type: DERIV" exp))))

这个deriv过程包含了完整的求导算法。由于它是用抽象数据表达的，无论我们选择如何表示代数表达式，只要设计了一组合适的选择函数和构造函数，它都能工作。这是我们接下来必须处理的问题。

表示代数表达式

我们可以想象许多使用表结构来表示代数表达式的方法。例如，我们可以使用反映通常代数记号的符号表，将 a x + b 表示为表(a * x + b)。然而，一个特别直接的选择是使用Lisp用于组合式的相同带括号的前缀表示法；也就是说，将 a x + b 表示为(+ (* a x) b)。那么我们的求导问题的数据表示如下：

  • 变量是符号。它们由基本谓词symbol?识别：
    (define (variable? x) (symbol? x))
  • 如果表示两个变量的符号是eq?，则这两个变量相同：
    (define (same-variable? v1 v2)
  (and (variable? v1)
       (variable? v2)
       (eq? v1 v2)))
  • 和与积被构造为表：
    (define (make-sum a1 a2) (list '+ a1 a2))
(define (make-product m1 m2) (list '* m1 m2))
  • 和是一个表，其第一个元素是符号+：
    (define (sum? x)
  (and (pair? x) (eq? (car x) '+)))
  • 加数是和表的第二个项：
    (define (addend s) (cadr s))
  • 被加数是和表的第三个项：
    (define (augend s) (caddr s))
  • 积是一个表，其第一个元素是符号*：
    (define (product? x)
  (and (pair? x) (eq? (car x) '*)))
  • 乘数是积表的第二个项：
    (define (multiplier p) (cadr p))
  • 被乘数是积表的第三个项：
    (define (multiplicand p) (caddr p))

因此，我们只需将这些与deriv所体现的算法结合起来，就能拥有一个可工作的符号求导程序。让我们看一些其行为的例子：

(deriv '(+ x 3) 'x)
(+ 1 0)

(deriv '(* x y) 'x)
(+ (* x 0) (* 1 y))

(deriv '(* (* x y) (+ x 3)) 'x)
(+ (* (* x y) (+ 1 0))
   (* (+ (* x 0) (* 1 y))
      (+  x 3)))

程序产生的答案是正确的；然而，它们未化简。确实 d ( x y ) d x = x ⋅ 0 + 1 ⋅ y , ，但我们希望程序知道 x ⋅ 0 = 0 、 1 ⋅ y = y 和 0 + y = y 。第二个例子的答案本应只是y。如第三个例子所示，当表达式复杂时，这成为一个严重的问题。

我们的困难很像我们在有理数实现中遇到的困难：我们还没有将答案化为最简形式。为了实现有理数化简，我们只需要改变实现中的构造函数和选择函数。我们可以在这里采用类似的策略。我们完全不改变deriv。相反，我们将改变make-sum，使得如果两个加数都是数字，make-sum将把它们相加并返回它们的和。此外，如果其中一个加数是0，那么make-sum将返回另一个加数：

(define (make-sum a1 a2)
  (cond ((=number? a1 0) a2)
        ((=number? a2 0) a1)
        ((and (number? a1) (number? a2)) 
         (+ a1 a2))
        (else (list '+ a1 a2))))

这使用了过程=number?，它检查一个表达式是否等于给定的数字：

(define (=number? exp num)
  (and (number? exp) (= exp num)))

类似地，我们将改变make-product，加入以下规则：0乘以任何东西是0，1乘以任何东西是那个东西本身：

(define (make-product m1 m2)
  (cond ((or (=number? m1 0) 
             (=number? m2 0)) 
         0)
        ((=number? m1 1) m2)
        ((=number? m2 1) m1)
        ((and (number? m1) (number? m2)) 
         (* m1 m2))
        (else (list '* m1 m2))))

以下是这个版本在我们的三个例子上的工作方式：

(deriv '(+ x 3) 'x)
1

(deriv '(* x y) 'x)
y

(deriv '(* (* x y) (+ x 3)) 'x)
(+ (* x y) (* y (+ x 3)))

尽管这已经是相当大的改进了，但第三个例子表明，在我们得到一个将表达式转换成我们可能一致认为是“最简”形式的程序之前，还有很长的路要走。代数化简问题很复杂，原因之一是，对某个目的而言可能最简的形式，对另一个目的而言可能并非如此。

2.3.3实例：集合的表示

在前面的例子中，我们为两种复合数据对象建立了表示：有理数和代数表达式。在其中一个例子中，我们可以选择在构造时或选择时化简（约简）表达式，但除此之外，用表来表示这些结构的选择是直接的。当我们转向集合的表示时，表示的选择就不那么显而易见了。事实上，有许多可能的表示，它们在几个方面彼此显著不同。

非形式地说，集合就是互不相同的对象的汇集。为了给出更精确的定义，我们可以采用数据抽象的方法。也就是说，我们通过指定将用于集合上的操作来定义“集合”。这些操作是union-set、intersection-set、element-of-set?和adjoin-set。Element-of-set?是一个谓词，用于确定给定元素是否是集合的成员。Adjoin-set接受一个对象和一个集合作为参数，并返回一个包含原集合的元素以及被加入元素的集合。Union-set计算两个集合的并集，即包含出现在任一参数中的每个元素的集合。Intersection-set计算两个集合的交集，即只包含同时出现在两个参数中的元素的集合。从数据抽象的观点来看，我们可以自由地设计任何表示，只要它以与上述解释一致的方式实现这些操作。103

集合作为无序表

表示集合的一种方式是将其表示为元素的表，其中没有元素出现超过一次。空集由空表表示。在这种表示中，element-of-set?类似于2.3.1中的过程memq。它使用equal?而不是eq?，因此集合元素不必是符号：

(define (element-of-set? x set)
  (cond ((null? set) false)
        ((equal? x (car set)) true)
        (else (element-of-set? x (cdr set)))))

使用这个，我们可以编写adjoin-set。如果要加入的对象已经在集合中，我们只需返回该集合。否则，我们使用cons将对象添加到表示该集合的表中：

(define (adjoin-set x set)
  (if (element-of-set? x set)
      set
      (cons x set)))

对于intersection-set，我们可以使用递归策略。如果我们知道如何构造set2与set1的cdr的交集，我们只需要决定是否将set1的car包含在其中。但这取决于(car set1)是否也在set2中。下面是得到的过程：

(define (intersection-set set1 set2)
  (cond ((or (null? set1) (null? set2)) 
         '())
        ((element-of-set? (car set1) set2)
         (cons (car set1)
               (intersection-set (cdr set1) 
                                 set2)))
        (else (intersection-set (cdr set1) 
                                set2))))

在设计表示时，我们应该关注的问题之一是效率。考虑我们的集合操作所需的步数。由于它们都使用element-of-set?，这个操作的速度对整个集合实现的效率有重大影响。现在，为了检查一个对象是否是集合的成员，element-of-set?可能不得不扫描整个集合。（在最坏情况下，该对象最终不在集合中。）因此，如果集合有 n 个元素，element-of-set?可能需要多达 n 步。于是，所需的步数按 Θ ( n ) 增长。使用此操作的adjoin-set所需的步数也按 Θ ( n ) 增长。对于intersection-set，它对set1的每个元素执行一次element-of-set?检查，所需的步数按所涉及集合大小的乘积增长，对于两个大小为 n 的集合，即 Θ ( n 2 ) 。union-set也是如此。

作为有序表的集合

加速集合操作的一种方法是改变表示方式，使集合元素按递增顺序排列。为此，我们需要某种比较两个对象的方法，以便能说出哪个更大。例如，我们可以按字典序比较符号，或者约定某种为对象分配唯一编号的方法，然后通过比较相应的编号来比较元素。为简化讨论，我们只考虑集合元素是数字的情况，这样我们可以用>和<来比较元素。我们将通过按递增顺序列出元素来表示数字集合。我们上面的第一种表示允许以任意顺序列出元素来表示集合 { 1 , 3 , 6 , 10 } ，而我们的新表示只允许表(1 3 6 10)。

排序的一个优势体现在element-of-set?中：在检查某个项是否存在时，我们不再需要扫描整个集合。如果我们遇到一个比正在查找的项更大的集合元素，那么我们就知道该项不在集合中：

(define (element-of-set? x set)
  (cond ((null? set) false)
        ((= x (car set)) true)
        ((< x (car set)) false)
        (else (element-of-set? x (cdr set)))))

这节省了多少步？在最坏情况下，我们要找的项可能是集合中最大的元素，因此步数与无序表示相同。另一方面，如果我们查找许多不同大小的项，可以预期有时我们能在表接近开头的位置停止搜索，而其他时候我们仍然需要检查表的大部分。平均而言，我们应该预期需要检查集合中大约一半的元素。因此，所需的平均步数大约为 n / 2 。这仍然是 Θ ( n ) 增长，但平均而言，它确实将之前实现所需的步数缩减为原来的2分之一。

使用intersection-set可以获得更显著的加速。在无序表示中，此操作需要 Θ ( n 2 ) 步，因为我们对set1的每个元素都完整扫描了set2。但在有序表示中，我们可以使用更巧妙的方法。首先比较两个集合的初始元素x1和x2。如果x1等于x2，那么这就给出了交集的一个元素，而交集的其余部分是两个集合的cdr的交集。然而，假设x1小于x2。由于x2是set2中最小的元素，我们可以立即得出结论：x1不可能出现在set2中的任何位置，因此不在交集中。因此，交集等于set2与set1的cdr的交集。类似地，如果x2小于x1，那么交集由set1与set2的cdr的交集给出。以下是该过程：

(define (intersection-set set1 set2)
  (if (or (null? set1) (null? set2))
      '()
      (let ((x1 (car set1)) (x2 (car set2)))
        (cond ((= x1 x2)
               (cons x1 (intersection-set 
                         (cdr set1)
                         (cdr set2))))
              ((< x1 x2) (intersection-set 
                          (cdr set1) 
                          set2))
              ((< x2 x1) (intersection-set 
                          set1 
                          (cdr set2)))))))

为了估计此过程所需的步数，注意每一步我们都将交集问题归约为计算更小集合的交集——从set1或set2或两者中移除第一个元素。因此，所需的步数至多是set1和set2的大小之和，而不是像无序表示那样是大小之积。这是 Θ ( n ) 增长而不是 Θ ( n 2 ) ——即使对于中等大小的集合，这也是相当大的加速。

作为二叉树的集合

通过将集合元素排列成树的形式，我们可以比有序表表示做得更好。树的每个节点保存集合中的一个元素，称为该节点的“条目”，并链接到另外两个（可能为空的）节点。“左”链接指向小于该节点元素的元素，“右”链接指向大于该节点元素的元素。图2.16展示了一些表示集合 { 1 , 3 , 5 , 7 , 9 , 11 } 的树。同一个集合可以用多种不同的树来表示。对于有效表示，我们唯一要求的是左子树中的所有元素都小于节点条目，右子树中的所有元素都大于节点条目。

树表示的优点在于：假设我们想要检查一个数 x 是否包含在一个集合中。我们首先将 x 与顶层节点中的条目进行比较。如果 x 小于这个条目，我们就知道只需搜索左子树；如果 x 大于这个条目，我们就只需搜索右子树。现在，如果树是“平衡的”，那么这些子树中的每一个都将大约是原来大小的一半。因此，一步之内我们就将搜索大小为 n 的树的问题缩减为搜索大小为 n / 2 的树。由于树的大小在每一步都减半，我们应该预期搜索大小为 n 的树所需的步数按 Θ ( log ⁡ n ) 增长。104 对于大型集合，这将比之前的表示有显著的加速。

我们可以用表来表示树。每个节点将是一个包含三个元素的表：节点处的条目、左子树和右子树。左子树或右子树为空表，将表明那里没有连接的子树。我们可以用以下过程来描述这种表示：105

(define (entry tree) (car tree))
(define (left-branch tree) (cadr tree))
(define (right-branch tree) (caddr tree))
(define (make-tree entry left right)
  (list entry left right))

现在我们可以使用上述策略编写 element-of-set? 过程：

(define (element-of-set? x set)
  (cond ((null? set) false)
        ((= x (entry set)) true)
        ((< x (entry set))
         (element-of-set? 
          x 
          (left-branch set)))
        ((> x (entry set))
         (element-of-set? 
          x 
          (right-branch set)))))

向集合中添加一个条目也以类似方式实现，并且同样需要 Θ ( log ⁡ n ) 步。要添加一个条目 x，我们将 x 与节点条目进行比较，以确定 x 应该添加到右分支还是左分支，并且在将 x 添加到适当的分支后，我们将这个新构造的分支与原始条目和另一个分支拼在一起。如果 x 等于条目，我们就直接返回该节点。如果要求我们将 x 添加到一个空树中，我们生成一棵树，其条目为 x，左右分支均为空。以下是该过程：

(define (adjoin-set x set)
  (cond ((null? set) (make-tree x '() '()))
        ((= x (entry set)) set)
        ((< x (entry set))
         (make-tree 
          (entry set)
          (adjoin-set x (left-branch set))
          (right-branch set)))
        ((> x (entry set))
         (make-tree
          (entry set)
          (left-branch set)
          (adjoin-set x (right-branch set))))))

上述关于搜索树可以在对数步数内完成的说法，建立在树是“平衡的”这一假设之上，即每棵树的左子树和右子树具有大致相同数量的元素，因此每个子树包含其父树大约一半的元素。但是我们如何能确定我们构造的树将是平衡的？即使我们从一棵平衡树开始，用 adjoin-set 添加元素也可能产生不平衡的结果。由于新添加元素的位置取决于该元素与集合中已有条目的比较方式，我们可以预期，如果我们“随机地”添加元素，树平均而言将倾向于平衡。但这并不是保证。例如，如果我们从一个空集开始，并按顺序添加数字 1 到 7，我们最终会得到 图 2.17 所示的高度不平衡的树。在这棵树中，所有左子树都是空的，因此它相对于一个简单的有序表没有任何优势。解决这个问题的一种方法是定义一个操作，将任意树转换为具有相同元素的平衡树。然后我们可以在每几次 adjoin-set 操作之后执行这种转换，以保持我们的集合平衡。还有其他方法可以解决这个问题，其中大多数涉及设计新的数据结构，使得搜索和插入都可以在 Θ ( log ⁡ n ) 步内完成。106

集合与信息检索

我们已经考察了使用表来表示集合的各种选择，并看到了数据对象表示的选择如何对使用这些数据的程序的性能产生巨大影响。关注集合的另一个原因是，这里讨论的技术在涉及信息检索的应用中反复出现。

考虑一个包含大量独立记录的数据库，例如一家公司的人事档案或会计系统中的交易记录。典型的数据管理系统会花费大量时间访问或修改记录中的数据，因此需要一种高效的方法来访问记录。这是通过标识每条记录的一部分来作为标识键来实现的。键可以是任何能唯一标识记录的东西。对于人事档案，它可能是员工的ID号。对于会计系统，它可能是交易号。无论键是什么，当我们将记录定义为数据结构时，我们应该包含一个key选择过程，用于检索与给定记录关联的键。

现在我们将数据库表示为一组记录。为了定位具有给定键的记录，我们使用过程lookup，它接受一个键和一个数据库作为参数，并返回具有该键的记录，如果没有这样的记录则返回false。Lookup的实现方式几乎与element-of-set?相同。例如，如果记录集实现为无序表，我们可以使用

(define (lookup given-key set-of-records)
  (cond ((null? set-of-records) false)
        ((equal? given-key 
                 (key (car set-of-records)))
         (car set-of-records))
        (else 
         (lookup given-key 
                 (cdr set-of-records)))))

当然，有比无序表更好的方式来表示大型集合。必须“随机访问”记录的信息检索系统通常通过基于树的方法实现，例如前面讨论的二叉树表示。在设计这样的系统时，数据抽象的方法论可以大有帮助。设计者可以使用简单直接的表示（如无序表）创建初始实现。这对于最终系统来说是不合适的，但它可以用于提供一个“快速而粗糙”的数据库来测试系统的其余部分。之后，数据表示可以被修改得更加精巧。如果数据库是通过抽象选择函数和构造函数来访问的，那么这种表示的变化将不需要对系统的其余部分做任何修改。

2.3.4示例：霍夫曼编码树

本节练习利用表结构和数据抽象来操作集合与树，并将其应用于把数据表示为由一和零组成的序列（比特序列）的方法。例如，计算机中用于表示文本的 ASCII 标准编码，将每个字符编码为一个七比特的序列。使用七个比特，我们就能区分 2 7 种，也就是128种可能的不同字符。一般来说，如果要区分 n 个不同的符号，每个符号就需要使用 log 2 ⁡ n 个比特。如果我们的所有消息都由 A、B、C、D、E、F、G 和 H 这八个符号组成，就可以选择一种每个字符使用三个比特的编码，例如

A 000  C 010  E 100  G 110
B 001  D 011  F 101  H 111

使用此编码，消息

BACADAEAFABBAAAGAH

被编码为54位的字符串

001000010000011000100000101
000001001000000000110000111

诸如ASCII和上面的A到H编码之类的编码被称为定长编码，因为它们用相同数量的位表示消息中的每个符号。有时使用变长编码是有利的，其中不同的符号可以由不同数量的位表示。例如，摩尔斯电码对字母表中的每个字母不使用相同数量的点和划。特别是，最频繁的字母E由单个点表示。一般来说，如果我们的消息中某些符号出现非常频繁而某些非常罕见，我们可以通过为频繁符号分配较短的编码来更高效地编码数据（即，每条消息使用更少的位）。考虑以下A到H字母的替代编码：

A 0    C 1010  E 1100  G 1110
B 100  D 1011  F 1101  H 1111

使用此编码，与上面相同的消息被编码为字符串

100010100101101100011
010100100000111001111

此字符串包含42位，因此与上面显示的定长编码相比，它节省了超过20%的空间。

使用变长码的困难之一是在读取由零和一组成的序列时，如何知道已经到达了一个符号的末尾。摩尔斯电码通过在表示每个字母的点划序列之后使用一个特殊的分隔码（在这里是一个停顿）来解决这个问题。另一种解决方案是设计这样的编码：任何符号的完整编码都不是另一个符号编码的开头（或前缀）。这样的编码称为前缀码。在上面的例子中，A 编码为0，B 编码为100，因此没有其他符号的编码可以以0或100开头。

一般来说，如果我们使用变长前缀码，利用要编码的消息中符号的相对频率，我们可以获得显著的节省。用于此目的的一种特定方案称为霍夫曼编码方法，以其发现者David Huffman命名。霍夫曼编码可以表示为一棵二叉树，其叶子是所编码的符号。在树的每个非叶节点处，有一个包含该节点下方叶子中所有符号的集合。此外，叶子处的每个符号被赋予一个权重（即其相对频率），每个非叶节点包含一个权重，该权重是其下方所有叶子权重的总和。权重不用于编码或解码过程。我们将在下面看到它们如何用于帮助构建树。

图 2.18 展示了上面给出的 A 到 H 编码的霍夫曼树。叶子上的权重表明，这棵树是为这样的消息设计的：其中 A 以相对频率 8 出现，B 以相对频率 3 出现，其他字母各以相对频率 1 出现。

给定一棵霍夫曼树，我们可以通过从根开始向下移动，直到到达保存该符号的叶子，来找到任何符号的编码。每次我们向下走左分支时，我们在编码中添加一个 0，每次我们向下走右分支时，我们添加一个 1。（我们通过测试哪个分支要么是该符号的叶节点，要么在其集合中包含该符号，来决定跟随哪个分支。）例如，从 图 2.18 中的树的根开始，我们通过依次走右分支、左分支、右分支、右分支，到达 D 的叶子；因此，D 的编码是 1011。

要使用霍夫曼树解码一个位序列，我们从根开始，使用位序列中连续的零和一来确定是向下走左分支还是右分支。每次我们到达一个叶子，我们就在消息中生成了一个新符号，此时我们从树的根重新开始，以找到下一个符号。例如，假设给定上面的树和序列 10001010。从根开始，我们向下走右分支（因为字符串的第一位是 1），然后向下走左分支（因为第二位是 0），然后向下走左分支（因为第三位也是 0）。这把我们带到 B 的叶子，所以解码消息的第一个符号是 B。现在我们再次从根开始，因为字符串中的下一位是 0，所以我们向左移动。这把我们带到 A 的叶子。然后我们用字符串的剩余部分 1010 再次从根开始，所以我们向右、向左、向右、向左移动，到达 C。因此，整个消息是 BAC。

生成霍夫曼树

给定一个符号的“字母表”及其相对频率，我们如何构造“最佳”编码？（换句话说，哪棵树将以最少的位编码消息？）霍夫曼给出了一种算法来做到这一点，并表明对于符号的相对频率与构造编码时所用的频率相匹配的消息，所得到的编码确实是最佳可变长度编码。我们不会在这里证明霍夫曼编码的这种最优性，但我们将展示霍夫曼树是如何构造的。108

生成霍夫曼树的算法非常简单。其思想是安排树，使得频率最低的符号出现在离根最远的地方。从叶子节点的集合开始，这些节点包含符号及其频率，由构造编码所依据的初始数据确定。现在找到两个权重最低的叶子，并将它们合并，产生一个以这两个节点作为其左分支和右分支的节点。新节点的权重是两个权重之和。从原始集合中移除这两个叶子，并用这个新节点替换它们。现在继续这个过程。在每一步，合并两个权重最小的节点，将它们从集合中移除，并用一个以这两个节点作为其左分支和右分支的节点替换它们。当只剩下一个节点时，过程停止，这个节点就是整棵树的根。下面是 图 2.18 的霍夫曼树是如何生成的：

Initial {(A 8) (B 3) (C 1) (D 1) 
leaves   (E 1) (F 1) (G 1) (H 1)}

Merge   {(A 8) (B 3) ({C D} 2) 
         (E 1) (F 1) (G 1) (H 1)}

Merge   {(A 8) (B 3) ({C D} 2) 
         ({E F} 2) (G 1) (H 1)}

Merge   {(A 8) (B 3) ({C D} 2) 
         ({E F} 2) ({G H} 2)}

Merge   {(A 8) (B 3) ({C D} 2) 
         ({E F G H} 4)}

Merge   {(A 8) ({B C D} 5) 
         ({E F G H} 4)}

Merge   {(A 8) ({B C D E F G H} 9)}

Final   {({A B C D E F G H} 17)}
merge

该算法并不总是指定唯一的树，因为在每一步可能没有唯一的最小权重节点。此外，合并两个节点的顺序选择（即哪个将是右分支，哪个将是左分支）是任意的。

表示霍夫曼树

在下面的练习中，我们将使用一个系统，该系统使用霍夫曼树来编码和解码消息，并根据上面概述的算法生成霍夫曼树。我们将从讨论树如何表示开始。

树的叶子由一个表表示，该表包含符号 leaf、叶子处的符号和权重：

(define (make-leaf symbol weight)
  (list 'leaf symbol weight))
(define (leaf? object)
  (eq? (car object) 'leaf))
(define (symbol-leaf x) (cadr x))
(define (weight-leaf x) (caddr x))

一般的树将是一个表，包含左分支、右分支、符号集合和权重。符号集合将简单地是一个符号的表，而不是某种更复杂的集合表示。当我们通过合并两个节点来构造一棵树时，我们得到树的权重为节点权重之和，符号集合为节点符号集合的并集。由于我们的符号集合表示为表，我们可以通过使用我们在 2.2.1 中定义的 append 过程来形成并集：

(define (make-code-tree left right)
  (list left
        right
        (append (symbols left) 
                (symbols right))
        (+ (weight left) (weight right))))

如果我们以这种方式构造一棵树，我们有以下选择函数：

(define (left-branch tree) (car tree))
(define (right-branch tree) (cadr tree))

(define (symbols tree)
  (if (leaf? tree)
      (list (symbol-leaf tree))
      (caddr tree)))

(define (weight tree)
  (if (leaf? tree)
      (weight-leaf tree)
      (cadddr tree)))

过程 symbols 和 weight 必须根据它们是用叶子还是一般树调用而略有不同。这些是 通用过程（可以处理多种数据的过程）的简单例子，我们将在 2.4 和 2.5 中对此有更多讨论。

解码过程

以下过程实现了解码算法。它接受一个由零和一组成的表，以及一棵霍夫曼树作为参数。

(define (decode bits tree)
  (define (decode-1 bits current-branch)
    (if (null? bits)
        '()
        (let ((next-branch
               (choose-branch 
                (car bits) 
                current-branch)))
          (if (leaf? next-branch)
              (cons 
               (symbol-leaf next-branch)
               (decode-1 (cdr bits) tree))
              (decode-1 (cdr bits) 
                        next-branch)))))
  (decode-1 bits tree))

(define (choose-branch bit branch)
  (cond ((= bit 0) (left-branch branch))
        ((= bit 1) (right-branch branch))
        (else (error "bad bit: 
               CHOOSE-BRANCH" bit))))

过程decode-1接受两个参数：剩余位的表和树中的当前位置。它不断沿着树“向下”移动，根据表中的下一位是零还是一来选择左分支或右分支。（这是通过过程choose-branch完成的。）当它到达叶子时，它将该叶子处的符号作为消息中的下一个符号返回，方法是将其cons到从树的根开始解码消息其余部分的结果上。注意choose-branch最后一个子句中的错误检查，如果过程在输入数据中发现零或一之外的东西，它就会报错。

带权元素的集合

在树的表示中，每个非叶子节点包含一个符号集合，我们将其表示为一个简单的表。然而，上面讨论的树生成算法要求我们也处理叶子和树的集合，依次合并两个最小的项。由于我们将需要反复找到集合中的最小项，因此对这类集合使用有序表示是方便的。

我们将叶子和树的集合表示为一个元素表，按权重递增排列。下面的adjoin-set过程用于构造集合，与习题2.61中描述的过程类似；然而，项按其权重进行比较，并且要添加的元素此前都不在集合中。

(define (adjoin-set x set)
  (cond ((null? set) (list x))
        ((< (weight x) (weight (car set))) 
         (cons x set))
        (else 
         (cons (car set)
               (adjoin-set x (cdr set))))))

下面的过程接受一个符号-频率对的表，例如((A 4) (B 2) (C 1) (D 1))，并构造一个初始的有序叶子集合，准备好根据 霍夫曼 算法进行合并：

(define (make-leaf-set pairs)
  (if (null? pairs)
      '()
      (let ((pair (car pairs)))
        (adjoin-set 
         (make-leaf (car pair)    ; symbol
                    (cadr pair))  ; frequency
         (make-leaf-set (cdr pairs))))))

习题2.67： 定义一个编码树和一个样本消息：

脚注

98 允许在语言中使用引用会严重破坏以简单术语推理语言的能力，因为它破坏了等量可以替换等量的观念。例如，三是一加二，但“三”这个词不是“一加二”这个短语。引用之所以强大，是因为它为我们提供了一种构造表达式来操作其他表达式的方法（正如我们在第4章编写解释器时将会看到的那样）。但是，允许语言中的语句谈论该语言中的其他语句，使得很难维持任何关于“等量可以替换等量”应该意味着什么的连贯原则。例如，如果我们知道昏星就是晨星，那么从语句“昏星是金星”我们可以推出“晨星是金星”。然而，给定“约翰知道昏星是金星”，我们不能推断出“约翰知道晨星是金星”。

99 单引号不同于我们一直用来括起要打印的字符串的双引号。单引号可以用来表示表或符号，而双引号仅用于字符串。在本书中，字符串的唯一用途是作为要打印的项。

100 严格来说，我们使用引号违反了通用规则，即我们语言中的所有复合表达式都应由括号界定并看起来像表。我们可以通过引入特殊形式quote来恢复这种一致性，它起到与引号相同的作用。因此，我们会输入(quote a)而不是'a，并且我们会输入(quote (a b c))而不是'(a b c)。解释器正是这样工作的。引号只是一个单字符缩写，用于将下一个完整表达式用quote包裹以形成(quote ⟨expression⟩)。这很重要，因为它维护了这样一个原则：解释器看到的任何表达式都可以作为数据对象来操作。例如，我们可以通过求值(list 'car (list 'quote '(a b c)))来构造表达式(car '(a b c))，它与(car (quote (a b c)))相同。

101 如果两个符号由相同顺序的相同字符组成，我们可以认为它们是“相同的”。这样的定义回避了一个我们尚未准备好解决的深层问题：编程语言中“相同性”的含义。我们将在第3章（3.1.3）中回到这个问题。

102 在实践中，程序员使用equal?来比较包含数字和符号的表。数字不被视为符号。两个数值相等的数字（由=测试）是否也是eq?的问题高度依赖于具体实现。一个更好的equal?定义（例如Scheme中作为基本过程提供的定义）还会规定，如果a和b都是数字，那么当a和b数值相等时，它们是equal?。

103 如果我们想要更形式化，我们可以将“与上述解释一致”指定为意味着这些操作满足一系列规则，例如以下这些：

  • 对于任何集合S和任何对象x，(element-of-set? x (adjoin-set x S))为真（非正式地说：“将一个对象加入集合产生一个包含该对象的集合”）。
  • 对于任何集合S和T以及任何对象x，(element-of-set? x (union-set S T))等于(or (element-of-set? x S) (element-of-set? x T))（非正式地说：“(union S T)的元素是那些在S中或在T中的元素”）。
  • 对于任何对象x，(element-of-set? x '())为假（非正式地说：“没有对象是空集的元素”）。

104 每一步将问题规模减半是对数增长的特征，正如我们在1.2.4的快速求幂算法和1.3.3的折半查找方法中所看到的那样。

105 我们用树来表示集合，用表来表示树——实际上，是在数据抽象之上构建的数据抽象。我们可以将过程entry、left-branch、right-branch和make-tree视为一种方式，将“二叉树”的抽象与我们可能希望用表结构来表示这种树的特定方式隔离开来。

106 这类结构的例子包括 B树和 红黑树。有大量关于数据结构的文献致力于这个问题。参见Cormen等人1990。
