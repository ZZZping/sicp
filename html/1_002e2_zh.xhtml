1.2过程及其产生的计算过程

我们现在已经考虑了编程的要素：我们使用了基本算术运算，组合了这些运算，并通过将它们定义为复合过程来抽象这些复合运算。但这还不足以让我们说我们知道如何编程。我们的情况类似于某人已经学会了国际象棋中棋子如何移动的规则，但对典型的开局、战术或策略一无所知。就像国际象棋新手一样，我们还不知道该领域中常见的用法模式。我们缺乏哪些走法值得走的知识（哪些过程值得定义）。我们缺乏预测走一步（执行一个过程）后果的经验。

能够想象所考虑行动后果的能力对于成为专家程序员至关重要，就像在任何综合性的、创造性的活动中一样。例如，在成为专家摄影师的过程中，必须学会观察一个场景，并知道对于每种可能的曝光和显影条件选择，每个区域在照片上会显得多暗。只有这样，才能反向推理，规划取景、照明、曝光和显影以获得期望的效果。编程也是如此，我们正在规划一个计算过程要采取的行动路线，并通过程序控制该过程。要成为专家，我们必须学会想象各种类型过程所产生的计算过程。只有在我们发展了这样的技能之后，我们才能学会可靠地构造表现出期望行为的程序。

过程是计算过程局部演化的一种模式。它规定了计算过程的每个阶段如何建立在前一阶段之上。对于局部演化已经由某个过程规定的计算过程，我们希望能够描述其整体行为，也就是全局行为。一般来说，这很难做到，但我们至少可以尝试描述计算过程演化的一些典型模式。

在本节中，我们将考察由简单过程生成的计算过程的一些常见“形状”。我们还将研究这些计算过程消耗重要计算资源——时间和空间——的速率。我们将考虑的过程非常简单。它们的作用就像摄影中的测试图案：作为过度简化的原型模式，而不是本身具有实用价值的例子。

1.2.1线性递归与迭代

我们从考虑阶乘函数开始，其定义为 n ! = n ⋅ ( n − 1 ) ⋅ ( n − 2 ) ⋯ 3 ⋅ 2 ⋅ 1. 计算阶乘有很多方法。一种方法是利用以下观察：对于任何正整数 n ， n ! 等于 n 乘以 ( n − 1 ) ! ： n ! = n ⋅ [ ( n − 1 ) ⋅ ( n − 2 ) ⋯ 3 ⋅ 2 ⋅ 1 ] = n ⋅ ( n − 1 ) ! . 因此，我们可以通过计算 ( n − 1 ) ! 并将结果乘以 n 来计算 n ! 。如果我们补充规定1!等于1，这个观察就直接转化为一个过程：

(define (factorial n)
  (if (= n 1) 
      1 
      (* n (factorial (- n 1)))))

我们可以使用1.1.5的代换模型来观察这个过程计算6!的过程，如图1.3所示。

现在让我们从不同的角度来看待阶乘的计算。我们可以通过指定先1乘以2，然后将结果乘以3，再乘以4，依此类推直到达到 n ，来描述计算 n ! 的规则。更形式化地说，我们维护一个累计乘积，以及一个从1计数到 n 的计数器。我们可以通过说计数器和乘积根据以下规则同时从一步变化到下一步来描述计算

product 
  ←
 counter * product
counter 
  ←
 counter + 1

并规定当计数器超过 n 时， n ! 是乘积的值。

再一次，我们可以将我们的描述改写为计算阶乘的过程：29

(define (factorial n) 
  (fact-iter 1 1 n))

(define (fact-iter product counter max-count)
  (if (> counter max-count)
      product
      (fact-iter (* counter product)
                 (+ counter 1)
                 max-count)))

和之前一样，我们可以使用代换模型来想象计算6!的过程，如图1.4所示。

比较这两个计算过程。从一个角度看，它们似乎几乎没有区别。两者都在相同的定义域上计算相同的数学函数，并且每个都需要与 n 成正比的步数来计算 n ! 。实际上，两个计算过程甚至执行相同的乘法序列，得到相同的部分乘积序列。另一方面，当我们考虑两个计算过程的“形状”时，我们发现它们的演化方式截然不同。

考虑第一个计算过程。代换模型揭示了一种先展开后收缩的形状，如图1.3中的箭头所示。展开发生在计算过程构建起一条延迟操作链（在这种情况下，是一系列乘法）时。收缩发生在操作实际执行时。这种以延迟操作链为特征的计算过程类型称为递归计算过程。执行这个计算过程要求解释器跟踪稍后要执行的操作。在计算 n ! 时，延迟乘法链的长度，以及因此跟踪它所需的信息量，随 n 线性增长（与 n 成正比），就像步数一样。这样的计算过程称为线性递归计算过程。

相比之下，第二个计算过程既不增长也不收缩。在每一步，对于任何 n ，我们需要跟踪的只是变量 product、counter 和 max-count 的当前值。我们称这是一个迭代计算过程。一般来说，迭代计算过程是其状态可以用固定数量的状态变量来概括的计算过程，再加上一个描述状态变量在计算过程从一个状态移动到另一个状态时应如何更新的固定规则，以及一个（可选的）结束测试，指定计算过程应终止的条件。在计算 n ! 时，所需的步数随 n 线性增长。这样的计算过程称为线性迭代计算过程。

这两个计算过程之间的对比还可以从另一个角度来看。在迭代的情况下，程序变量提供了计算过程在任意点的状态的完整描述。如果我们在步骤之间停止计算，要恢复计算，我们只需向解释器提供这三个程序变量的值。递归计算过程则不然。在这种情况下，存在一些额外的“隐藏”信息，由解释器维护而不包含在程序变量中，它指示在处理延迟操作链时“计算过程进行到了哪里”。链越长，必须维护的信息就越多。30

在对比迭代和递归时，我们必须注意不要将递归计算过程的概念与递归过程的概念相混淆。当我们把一个过程描述为递归的时，我们指的是过程定义（直接或间接）引用过程本身这一语法事实。但当我们把一个计算过程描述为遵循某种模式，比如线性递归时，我们谈论的是计算过程如何演化，而不是过程如何编写的语法。我们提到像fact-iter这样的递归过程生成一个迭代计算过程，这似乎令人不安。然而，该计算过程确实是迭代的：它的状态完全由它的三个状态变量所捕获，解释器只需跟踪三个变量就能执行该计算过程。

计算过程和过程之间的区别可能令人困惑的一个原因是，大多数常见语言（包括 Ada、Pascal 和 C）的实现方式使得对任何递归过程的解释都会消耗随过程调用次数增长的内存量，即使所描述的计算过程在原则上是迭代的。因此，这些语言只能借助特殊用途的“循环结构”如do、repeat、until、for和while来描述迭代计算过程。我们将在第5章考虑的 Scheme 实现没有这个缺陷。即使迭代计算过程是由递归过程描述的，它也会在常量空间中执行迭代计算过程。具有这种性质的实现称为尾递归。在尾递归实现中，迭代可以用普通的过程调用机制来表达，因此特殊的迭代结构仅作为语法糖有用。31

1.2.2树形递归

另一种常见的计算模式称为树形递归。作为一个例子，考虑计算斐波那契数列，其中每个数是前两个数之和：

0, 1, 1, 2, 3, 5, 8, 13, 21, ….

一般来说，斐波那契数可以由以下规则定义 Fib ( n ) = { 0 if n = 0 , 1 if n = 1 , Fib ( n − 1 ) + Fib ( n − 2 ) otherwise . 我们可以立即将这个定义翻译成计算斐波那契数的递归过程：

(define (fib n)
  (cond ((= n 0) 0)
        ((= n 1) 1)
        (else (+ (fib (- n 1))
                 (fib (- n 2))))))

考虑这个计算的模式。为了计算(fib 5)，我们计算(fib 4)和(fib 3)。为了计算(fib 4)，我们计算(fib 3)和(fib 2)。一般来说，演化的计算过程看起来像一棵树，如图1.5所示。注意，分支在每一层都分成两个（除了底部）；这反映了fib过程每次被调用时都调用自身两次这一事实。

这个过程作为典型的树形递归具有教育意义，但用它计算 斐波那契数却很糟糕，因为它做了太多冗余计算。注意图1.5中，(fib 3)的整个计算——几乎一半的工作——被重复了。事实上，不难证明，该过程计算(fib 1)或(fib 0)的次数（即上述树中叶节点的数目，一般而言）恰好是 Fib ( n + 1 ) 。为了了解这有多糟糕，可以证明 Fib ( n ) 的值随 n 呈指数增长。更确切地说（见习题1.13）， Fib ( n ) 是最接近 φ n / 5 的整数，其中 φ = 1 + 5 2 ≈ 1.6180 是黄金分割比，它满足方程 φ 2 = φ + 1. 。因此，该计算过程所需的步数随输入呈指数增长。另一方面，所需的空间仅随输入线性增长，因为在计算的任何时刻，我们只需要记录树中位于我们上方的节点。一般而言，树形递归计算过程所需的步数与树中的节点数成正比，而所需的空间与树的最大深度成正比。

我们也可以构造一个计算 斐波那契数的迭代计算过程。其思路是使用一对整数 a 和 b ，初始化为 Fib(1) = 1 和 Fib(0) = 0 ，并反复应用同时变换

a ← a + b , b ← a .

不难证明，在应用此变换 n 次之后， a 和 b 将分别等于 Fib ( n + 1 ) 和 Fib ( n ) 。因此，我们可以使用以下过程迭代地计算 斐波那契数

(define (fib n) 
  (fib-iter 1 0 n))

(define (fib-iter a b count)
  (if (= count 0)
      b
      (fib-iter (+ a b) a (- count 1))))

这第二种计算 Fib ( n ) 的方法是一个线性迭代。两种方法所需步数的差异——一种与 n 成线性关系，另一种增长得和 Fib ( n ) 本身一样快——是巨大的，即使对于很小的输入也是如此。

不应由此得出结论说树形递归计算过程是无用的。当我们考虑操作分层结构数据而非数的计算过程时，我们会发现树形递归是一种自然且强大的工具。32但即使在数值运算中，树形递归计算过程也有助于我们理解和设计程序。例如，尽管第一个fib过程比第二个效率低得多，但它更直截了当，几乎只是将 斐波那契数列的定义翻译成 Lisp。要构造迭代算法，需要注意到计算可以重新表述为具有三个状态变量的迭代。

示例：换零钱方式的计数

只需一点巧思，就能想出迭代式的斐波那契算法。相比之下，请考虑下面这个问题：给定半美元、二十五美分、十美分、五美分和一美分的硬币，把 $1.00 换成零钱共有多少种不同的方法？更一般地说，我们能否写出一个过程，计算将任意给定金额换成零钱的方法数？

这个问题作为递归过程有一个简单的解法。假设我们将可用的硬币种类按某种顺序排列。那么以下关系成立：

将金额 a 用 n 种硬币换成零钱的方式数等于

  • 将金额 a 用除第一种硬币外的所有硬币换成零钱的方式数，加上
  • 将金额 a − d 用所有 n 种硬币换成零钱的方式数，其中 d 是第一种硬币的面额。

要理解为什么这是正确的，请注意，换零钱的方式可以分为两组：不使用任何第一种硬币的方式，以及使用第一种硬币的方式。因此，将某个金额换成零钱的总方式数等于不使用任何第一种硬币将该金额换成零钱的方式数，加上假设我们使用第一种硬币将该金额换成零钱的方式数。但后一个数目等于使用一枚第一种硬币后剩余金额换成零钱的方式数。

因此，我们可以递归地将给定金额的换零钱问题归约为使用更少种类硬币的较小金额的换零钱问题。仔细考虑这个归约规则，并说服自己，如果我们指定以下退化情况，就可以用它来描述一个算法：33

  • 如果 a 恰好为0，我们应将其计为1种换零钱方式。
  • 如果 a 小于0，我们应将其计为0种换零钱方式。
  • 如果 n 为0，我们应将其计为0种换零钱方式。

我们可以轻松地将此描述翻译成一个递归过程：

(define (count-change amount)
  (cc amount 5))

(define (cc amount kinds-of-coins)
  (cond ((= amount 0) 1)
        ((or (< amount 0) 
             (= kinds-of-coins 0)) 
         0)
        (else 
         (+ (cc amount (- kinds-of-coins 1))
            (cc (- amount (first-denomination 
                           kinds-of-coins))
                kinds-of-coins)))))

(define (first-denomination kinds-of-coins)
  (cond ((= kinds-of-coins 1) 1)
        ((= kinds-of-coins 2) 5)
        ((= kinds-of-coins 3) 10)
        ((= kinds-of-coins 4) 25)
        ((= kinds-of-coins 5) 50)))

（first-denomination过程以可用硬币种类数为输入，返回第一种硬币的面额。这里我们考虑硬币按从大到小的顺序排列，但任何顺序都可以。）我们现在可以回答关于换一美元零钱的原始问题了：

(count-change 100)
292

Count-change生成一个树形递归计算过程，其冗余类似于我们第一个fib实现中的冗余。（计算那个292将需要相当长的时间。）另一方面，如何设计一个更好的算法来计算结果并不明显，我们将此问题留作挑战。树形递归计算过程可能效率极低，但通常易于指定和理解，这一观察促使人们提出，可以通过设计一个“智能编译器”来将树形递归过程转换为计算相同结果的更高效过程，从而兼得两者之长。34

1.2.3增长阶

前面的例子说明，计算过程在消耗计算资源的速率上可能差别很大。描述这种差异的一种方便的方法是使用增长阶的概念，以便在输入变得更大时获得计算过程所需资源的粗略度量。

令 n 为一个度量问题规模的参数，并令 R ( n ) 为计算过程对规模为 n 的问题所需的资源量。在我们之前的例子中，我们取 n 为要计算给定函数的那个数，但还有其他可能性。例如，如果我们的目标是计算一个数的平方根的近似值，我们可以取 n 为所需的精确位数。对于矩阵乘法，我们可以取 n 为矩阵的行数。一般来说，问题有许多属性，针对这些属性来分析给定的计算过程是可取的。类似地， R ( n ) 可以度量所使用的内部存储寄存器的数量、执行的基本机器操作的次数，等等。在每次只能执行固定数量操作的计算机中，所需的时间将与所执行的基本机器操作的次数成正比。

我们说 R ( n ) 具有增长阶 Θ ( f ( n ) ) ，记作 R ( n ) = Θ ( f ( n ) ) （读作“ f ( n ) 的 theta”），如果存在与 n 无关的正常数 k 1 和 k 2 ，使得对于任意足够大的 n 值都有 k 1 f ( n ) ≤ R ( n ) ≤ k 2 f ( n ) 。（换句话说，对于大的 n ，值 R ( n ) 被夹在 k 1 f ( n ) 和 k 2 f ( n ) 之间。）

例如，对于 1.2.1 中描述的用于计算阶乘的线性递归计算过程，步数按与输入 n 成比例的方式增长。因此，此计算过程所需的步数按 Θ ( n ) 增长。我们还看到所需的空间按 Θ ( n ) 增长。对于迭代式阶乘，步数仍然是 Θ ( n ) ，但空间是 Θ ( 1 ) ——即常数。36 树形递归的 斐波那契 计算需要 Θ ( φ n ) 步和 Θ ( n ) 空间，其中 φ 是 1.2.2 中描述的黄金分割比。

增长阶仅提供对计算过程行为的粗略描述。例如，一个需要 n 2 步的计算过程、一个需要 1000 n 2 步的计算过程和一个需要 3 n 2 + 10 n + 17 步的计算过程都具有 Θ ( n 2 ) 增长阶。另一方面，增长阶提供了一个有用的指示，说明当我们改变问题规模时，我们可以预期计算过程的行为如何变化。对于一个 Θ ( n ) （线性）计算过程，规模加倍将大致使所使用的资源量加倍。对于一个指数计算过程，问题规模每增加一个单位，资源使用量将乘以一个常数因子。在 1.2 的剩余部分中，我们将考察两个增长阶为对数的算法，因此问题规模加倍只会使资源需求增加一个常数。

1.2.4求幂

考虑计算给定数的幂的问题。我们希望有一个过程，它接受一个底数 b 和一个正整数指数 n 作为参数，并计算 b n 。做到这一点的一种方式是通过递归定义 b n = b ⋅ b n − 1 , b 0 = 1 , ，这可以很容易地转化为过程

(define (expt b n)
  (if (= n 0) 
      1 
      (* b (expt b (- n 1)))))

这是一个线性递归计算过程，需要 Θ ( n ) 步和 Θ ( n ) 空间。正如阶乘一样，我们可以很容易地构造一个等价的线性迭代：

(define (expt b n) 
  (expt-iter b n 1))

(define (expt-iter b counter product)
  (if (= counter 0)
      product
      (expt-iter b
                 (- counter 1)
                 (* b product))))

这个版本需要 Θ ( n ) 步和 Θ ( 1 ) 空间。

我们可以通过使用逐次平方来以更少的步数求幂。例如，与其将 b 8 计算为 b ⋅ ( b ⋅ ( b ⋅ ( b ⋅ ( b ⋅ ( b ⋅ ( b ⋅ b ) ) ) ) ) ) , ，我们可以用三次乘法来计算它： b 2 = b ⋅ b , b 4 = b 2 ⋅ b 2 , b 8 = b 4 ⋅ b 4 . 这种方法对于指数是 2 的幂的情况效果很好。如果我们使用规则 b n = ( b n / 2 ) 2 if n is even , b n = b ⋅ b n − 1 if n is odd . ，我们也可以利用逐次平方来一般地求幂。我们可以将此方法表示为一个过程：

(define (fast-expt b n)
  (cond ((= n 0) 
         1)
        ((even? n) 
         (square (fast-expt b (/ n 2))))
        (else 
         (* b (fast-expt b (- n 1))))))

其中用于测试一个整数是否为偶数的谓词是根据基本过程 remainder 定义的：

(define (even? n)
  (= (remainder n 2) 0))

由 fast-expt 演化的计算过程在空间和步数上都随 n 对数增长。要看到这一点，请注意使用 fast-expt 计算 b 2 n 只比计算 b n 多一次乘法。因此，我们所能计算的指数的大小（大约）随着我们被允许进行的每一次新乘法而加倍。于是，对于指数 n 所需的乘法次数大约以 n 的以 2 为底的对数的速度增长。该计算过程具有 Θ ( log ⁡ n ) 增长。37

随着 n 变大， Θ ( log ⁡ n ) 增长与 Θ ( n ) 增长之间的差异变得惊人。例如，对于 n = 1000，fast-expt 只需要 14 次乘法。38 也可以利用逐次平方的思想来设计一种以对数步数求幂的迭代算法（见 习题 1.16），尽管正如迭代算法常见的情况那样，这并不像递归算法那样直截了当地写出来。39

1.2.5最大公约数

两个整数 a 和 b 的最大公约数（GCD）定义为能同时整除 a 和 b 而无余数的最大整数。例如，16和28的GCD是4。在第2章中，当我们研究如何实现有理数算术时，我们将需要能够计算GCD，以便将有理数化为最简形式。（要将有理数化为最简形式，我们必须将分子和分母都除以它们的GCD。例如，16/28化为4/7。）求两个整数的GCD的一种方法是将它们分解并寻找公因子，但有一个著名算法要高效得多。

该算法的思想基于以下观察：如果 r 是 a 除以 b 的余数，那么 a 和 b 的公约数恰好与 b 和 r 的公约数相同。因此，我们可以使用等式

GCD(a,b) = GCD(b,r)

来逐步将计算GCD的问题归约为计算越来越小的整数对的GCD的问题。例如，

GCD(206,40) = GCD(40,6)
            = GCD(6,4)
            = GCD(4,2)
            = GCD(2,0) = 2

将GCD(206, 40)归约为GCD(2, 0)，即2。可以证明，从任意两个正整数开始并反复进行这种归约，最终总会产生一个第二个数为0的序对。那么GCD就是该序对中的另一个数。这种计算GCD的方法被称为欧几里得算法。42

很容易将欧几里得算法表示为一个过程：

(define (gcd a b)
  (if (= b 0)
      a
      (gcd b (remainder a b))))

这生成一个迭代计算过程，其步数随所涉及数字的对数增长。

欧几里得算法所需步数具有对数增长这一事实，与斐波那契数有着有趣的关系：

拉梅定理：如果欧几里得算法需要 k 步来计算某一序对的GCD，那么该序对中较小的数必定大于或等于第 k th 个斐波那契数。43

我们可以用这个定理来得到欧几里得算法的增长阶估计。设 n 为该过程两个输入中较小的那个。如果计算过程需要 k 步，那么必有 n ≥ Fib ( k ) ≈ φ k / 5 。因此步数 k 随 n 的对数（以 φ 为底）增长。所以，增长阶为 Θ ( log ⁡ n ) 。

1.2.6示例：检测素数

本节描述两种检查整数 n 是否为素数的方法，一种的增长阶为 Θ ( n ) ，另一种是“概率”算法，增长阶为 Θ ( log ⁡ n ) 。本节末尾的练习给出了基于这些算法的编程项目。

寻找因子

自古以来，数学家们就对与素数有关的问题着迷，许多人致力于研究确定数是否为素数的方法。检验一个数是否为素数的一种方法是找出该数的因子。下面的程序找出给定数 n 的最小整数因子（大于 1）。它以一种直接的方式做到这一点，即从 2 开始，用连续的整数测试 n 是否能被整除。

(define (smallest-divisor n)
  (find-divisor n 2))

(define (find-divisor n test-divisor)
  (cond ((> (square test-divisor) n) 
         n)
        ((divides? test-divisor n) 
         test-divisor)
        (else (find-divisor 
               n 
               (+ test-divisor 1)))))

(define (divides? a b)
  (= (remainder b a) 0))

我们可以如下检验一个数是否为素数： n 是素数当且仅当 n 是它自己的最小因子。

(define (prime? n)
  (= n (smallest-divisor n)))

find-divisor 的终止测试基于这样一个事实：如果 n 不是素数，那么它必定有一个小于或等于 n 的因子。44 这意味着算法只需测试 1 到 n 之间的因子。因此，确定 n 为素数所需的步数将具有增长阶 Θ ( n ) 。

费马检验

Θ ( log ⁡ n ) 素性检验基于数论中一个称为费马小定理的结果。45

费马小定理： 如果 n 是一个素数，而 a 是任何小于 n 的正整数，那么 a 的 n th 次幂与 a 模 n 同余。

（如果两个数除以 n 时余数相同，就称它们模 n 同余。一个数 a 除以 n 的余数也称为 a 模 n 的余数，或者简称为 a 模 n 。）

如果 n 不是素数，那么一般来说，大多数数 a < n 都不会满足上述关系。这引出了以下检验素性的算法：给定一个数 n ，随机选取一个数 a < n 并计算 a n 模 n 的余数。如果结果不等于 a ，那么 n 肯定不是素数。如果结果等于 a ，那么 n 很可能是素数。现在再随机选取另一个数 a 并用同样的方法检验。如果它也满足该等式，那么我们可以更加确信 n 是素数。通过尝试越来越多的 a 值，我们可以增加对结果的信心。这个算法被称为费马检验。

为了实现费马检验，我们需要一个计算一个数的幂模另一个数的过程：

(define (expmod base exp m)
  (cond ((= exp 0) 1)
        ((even? exp)
         (remainder 
          (square (expmod base (/ exp 2) m))
          m))
        (else
         (remainder 
          (* base (expmod base (- exp 1) m))
          m))))

这与 1.2.4 中的 fast-expt 过程非常相似。它使用逐次平方，因此步数随指数呈对数增长。46

费马检验通过随机选取一个介于 1 和 n − 1 之间（含两端）的数 a ，并检查 a 的 n th 次幂模 n 的余数是否等于 a 来进行。随机数 a 使用过程 random 选取，我们假定它在 Scheme 中作为基本过程提供。Random 返回一个小于其整数输入的非负整数。因此，要获得介于 1 和 n − 1 之间的随机数，我们以 n − 1 为输入调用 random，并将结果加上 1：

(define (fermat-test n)
  (define (try-it a)
    (= (expmod a n n) a))
  (try-it (+ 1 (random (- n 1)))))

下面的过程按参数指定的次数运行检验。如果每次检验都成功，其值为真，否则为假。

(define (fast-prime? n times)
  (cond ((= times 0) true)
        ((fermat-test n) 
         (fast-prime? n (- times 1)))
        (else false)))
概率方法

费马检验在性质上与大多数熟悉的算法不同，后者计算出的答案是保证正确的。在这里，得到的答案只是可能正确。更准确地说，如果 n 未能通过费马检验，我们可以确定 n 不是素数。但是 n 通过检验这一事实，虽然是一个极强的迹象，仍然不能保证 n 是素数。我们想说的是，对于任何数 n ，如果我们进行足够多次检验并发现 n 总是通过检验，那么我们的素性检验中出错的概率可以做到任意小。

不幸的是，这个断言并不完全正确。确实存在能骗过费马检验的数：那些不是素数，却具有如下性质的数 n ：对于所有整数 a < n ， a n 与 a 模 n 同余。这样的数极其罕见，因此费马检验在实践中相当可靠。47

有一些费马测试的变体是不会被欺骗的。在这些测试中，与费马方法一样，人们通过选择一个随机整数 a < n 并检查某个依赖于 n 和 a 的条件来测试整数 n 的素性。（关于这种测试的一个例子，参见 习题 1.28。）另一方面，与费马测试不同，人们可以证明，对于任何 n ，除非 n 是素数，否则该条件对大多数整数 a < n 不成立。因此，如果 n 在随机选择某个 a 时通过了测试，那么 n 是素数的概率比一半还大。如果 n 在随机选择两个 a 时通过了测试，那么 n 是素数的概率大于 4 分之 3。通过用越来越多随机选择的 a 值运行测试，我们可以使错误的概率小到我们想要的任何程度。

对于那些可以证明出错概率变得任意小的测试，其存在激发了人们对这类算法的兴趣，这类算法后来被称为 概率算法。这一领域有大量的研究活动，概率算法已被富有成效地应用于许多领域。48

43 这个定理是由加布里埃尔·拉梅于1845年证明的，他是一位法国数学家和工程师，主要以对数学物理的贡献而闻名。为了证明这个定理，我们考虑序对 ( a k , b k ) ，其中 a k ≥ b k ，对于这些序对，欧几里得算法在 k 步后终止。证明基于这样一个论断：如果在归约过程中 ( a k + 1 , b k + 1 ) → ( a k , b k ) → ( a k − 1 , b k − 1 ) 是三个相继的序对，那么我们必须有 b k + 1 ≥ b k + b k − 1 。为了验证这个论断，考虑归约步骤是由应用变换 a k − 1 = b k ， b k − 1 = a k 除以 b k 的余数来定义的。第二个等式意味着对于某个正整数 q ，有 a k = q b k + b k − 1 。并且由于 q 必须至少为1，我们有 a k = q b k + b k − 1 ≥ b k + b k − 1 。但在前一个归约步骤中我们有 b k + 1 = a k 。因此， b k + 1 = a k ≥ b k + b k − 1 。这验证了该论断。现在我们可以通过对 k ，即算法终止所需的步数，进行归纳来证明这个定理。对于 k = 1 ，结果是成立的，因为这仅仅要求 b 至少与 Fib ( 1 ) = 1 一样大。现在，假设对于所有小于或等于 k 的整数结果都成立，并确立 k + 1 的结果。设 ( a k + 1 , b k + 1 ) → ( a k , b k ) → ( a k − 1 , b k − 1 ) 为归约过程中的相继序对。根据我们的归纳假设，我们有 b k − 1 ≥ Fib ( k − 1 ) 和 b k ≥ Fib ( k ) 。因此，应用我们刚刚证明的论断以及斐波那契数的定义，得到 b k + 1 ≥ b k + b k − 1 ≥ Fib ( k ) + Fib ( k − 1 ) = Fib ( k + 1 ) ，这就完成了拉梅定理的证明。

45 Pierre de Fermat（1601-1665）被认为是现代数论的奠基人。他获得了许多重要的数论结果，但他通常只宣布结果，而不提供证明。费马小定理是在他1640年写的一封信中陈述的。第一个发表的证明由 Euler 在1736年给出（并且在 Leibniz 未发表的手稿中发现了一个更早的、相同的证明）。费马最著名的结果——被称为费马大定理——是在1637年草草写在他那本Arithmetic（由三世纪希腊数学家 Diophantus 所著）的副本中的，并附有评论“我发现了一个真正非凡的证明，但这个页边空白太小，写不下。”寻找费马大定理的证明成为数论中最著名的挑战之一。完整的解答最终由普林斯顿大学的 Andrew Wiles 在1995年给出。

46 在指数 e 大于1的情况下的归约步骤基于以下事实：对于任意整数 x 、 y 和 m ，我们可以通过分别计算 x 模 m 的余数和 y 模 m 的余数，将它们相乘，然后对结果取模 m 的余数，来求得 x 乘以 y 模 m 的余数。例如，在 e 为偶数的情况下，我们计算 b e / 2 模 m 的余数，将其平方，然后取模 m 的余数。这项技术很有用，因为它意味着我们可以在进行计算时，永远不必处理远大于 m 的数。（比较习题1.25。）

47 能骗过费马测试的数被称为 Carmichael 数，除了它们极其罕见之外，人们对它们知之甚少。在100,000,000以下有255个 Carmichael 数。最小的几个是561、1105、1729、2465、2821和6601。在测试随机选取的非常大的数的素性时，碰巧遇到一个能骗过费马测试的值的概率，小于宇宙辐射导致计算机在执行“正确”算法时出错的概率。认为一个算法因第一个原因而不适用，但不因第二个原因而不适用，这说明了数学与工程之间的区别。

48概率素数检测最引人注目的应用之一是在密码学领域。虽然目前从计算上说，还无法实际完成对任意200位数的因数分解，但利用费马测试，只需几秒就能检测这样一个数的素性。这一事实构成了Rivest 等人（1977）提出的一种构造“不可破解密码”的技术的基础。由此产生的RSA 算法已成为广泛用于增强电子通信安全性的技术。由于这一进展及其他相关进展，素数研究如今在密码学、电子资金转账和信息检索中有了重要的实际应用，而它曾被视为“纯”数学课题的典范，似乎只值得为研究本身而研究。
